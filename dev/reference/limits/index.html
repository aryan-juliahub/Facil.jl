Limits

This page states plainly what Facil does not do, where its limits are and what happens at each one. Read it before you commit to Facil for a project; nothing here is hidden elsewhere.

Protocol and platform

  • HTTP/1.1 and HTTP/1.0 only. No HTTP/2, no HTTP/3. Put a reverse proxy in front if browsers must reach you over HTTP/2 (Deployment).
  • Linux and macOS only. On Windows, run Facil inside WSL2. See Platform support.
  • A C compiler is needed to install, until the prebuilt library is published, and the package is not in the General registry yet (Install).

The keyword limits are per server; see Configuration.

  • The 408 is sent to a client that is still trickling its request head when header_timeout expires. A client that sends part of a head and then nothing is closed without a response when the idle timeout expires.
  • Paths and query strings are not percent-decoded and not split. path(uri(req)) is what the client sent. Decode with URIs.jl (Reading requests).
  • A request line with stray spaces (GET /a b HTTP/1.1) is not rejected: the handler sees the target up to the first space and the connection is closed after the response.

Response behaviour to know about

  • Status codes that facil.io does not know are sent as 500. That is every unregistered code (299, 599) and two registered ones: 418 and 451. Headers and body are sent as given; only the status line is wrong. All other registered codes in StatusCodes are sent correctly.
  • date, last-modified and connection are added to every non-streamed response that does not set them. last-modified is the time of the response, which tells caches the content just changed; set your own last-modified or cache-control on anything you want cached.
  • Streamed responses carry no date header.
  • content-length and transfer-encoding are set by Facil. Values you set are ignored.
  • A 204 or 304 response keeps a body if you give it one. Do not give it one.
  • Response bodies are sent without a copy. Do not change a Vector{UInt8} after returning it from a handler or writing it to a stream.
  • Each write to a streamed response is one chunk on the wire.
  • A streamed response to an HTTP/1.0 client ends by closing the connection. After an event stream (sse) the connection is closed.

Handlers, threads and the reactor

  • One reactor per process, shared by every server. reactors is fixed by the first server started.
  • Task handlers need more than one Julia thread. With julia -t 1 every handler runs inline on the reactor thread, whatever inline says.
  • Anything that runs on the reactor thread must not block: inline handlers, before_body, Stream(on_chunk), WebSocket callbacks without spawn = true, subscribe(f, channel) callbacks without spawn = true. One that blocks stalls every connection on that thread.
  • HTTPS needs reactors = 1.
  • No disconnect detection during a handler, and no cancellation. A client that goes away while its handler runs is not noticed; the handler finishes and the result is discarded. Streamed responses and event streams do notice (isopen).
  • Garbage collection pauses request handling. A collection stops every thread, the reactor included. See Performance tuning for sizes and remedies.
  • The SIGTERM drain does not finish handlers that are waiting on I/O. After the signal Julia's event loop no longer runs, so only handlers that are computing or in Facil.sleep complete; a handler waiting on a socket, a process or Base.sleep is lost after the grace period. Call close(server; grace) before stopping the process. On Julia 1.10 the SIGTERM drain is unreliable for all handlers. See Shutdown and signals.
  • Ctrl-C stops serve cleanly only at the REPL. In a script Julia prints its interrupt report first; under julia -e, or with Base.exit_on_sigint(false), Ctrl-C does not stop the server at all. Use SIGTERM. See Shutdown and signals.

Static files

Measured behaviour of public_folder and sendfile:

  • cache-control: max-age=3600 is always sent and cannot be changed.
  • If-None-Match is honoured; If-Modified-Since is ignored.
  • One byte range is served (206); a request for several ranges gets the whole file (200).
  • A directory path without a trailing slash is not redirected.
  • Files whose names start with a dot are served, and symbolic links are followed, including links that point outside the folder.
  • The etag is derived from size and modification time.

See Static files.

Not included

  • No router, no middleware framework, no templates, no cookie or session helpers, no multipart or form parser, no CORS helper. Handlers are plain functions; the guides show how to write each of these in a few lines where it is short (Routing, Security).
  • No HTTP client. Use Downloads (bundled with Julia) or HTTP.jl as a client.
  • No worker processes (fork, cluster). Scale with threads.
  • Pub/sub is local to the process. facil.io's Redis engine is not wrapped.
  • The client certificate of a mutual-TLS connection is not exposed to the handler; it is only verified.
  • Existing HTTP.jl handlers and routers do not plug in. They need porting to HttpTypes; see Coming from HTTP.jl.
