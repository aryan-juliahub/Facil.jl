Tutorial: a JSON API

This tutorial builds a small but complete web service in about ten minutes: a notes API with routing, path and query parameters, JSON in and out, proper error responses and a test. At the end you run it and call it with curl.

You need Facil installed (Install) and two more packages for JSON and for decoding query strings:

julia --project=. -e 'using Pkg; Pkg.add(["JSON", "URIs"])'

The finished program is one file, notes.jl. Each section below adds a part of it; the whole file is at the end of the page.

The API

RequestDoesSuccess
GET /noteslist notes, optionally filtered with ?q=text200, a JSON array
POST /notescreate a note from a JSON object with title and text201, the note, and a location header
GET /notes/{id}fetch one note200, the note
DELETE /notes/{id}delete a note204, no body
GET /healthliveness check for a load balancer200, ok

Errors are JSON too: {"error": "..."} with a fitting status.

1. Storage

The notes live in memory, in a Dict.

struct Note
    id::Int
    title::String
    text::String
end

const NOTES = Dict{Int,Note}()
const NOTES_LOCK = ReentrantLock()
const NEXT_ID = Ref(1)

The lock matters. Facil runs handlers on several threads at once (that is what julia -t 4 gives you), so two requests can touch NOTES at the same moment. Every access to shared state needs a lock, exactly as in any threaded Julia program.

2. Two helpers

Every response of this API is JSON, so wrap that once:

const JSON_TYPE = [header.CONTENT_TYPE => "application/json"]

json(status, data) = Response(status, JSON.json(data); headers = JSON_TYPE)
problem(status, message) = json(status, (error = message,))

JSON.json turns a struct, a named tuple, a Dict or a vector into JSON text. Facil does not set content-type: application/json for you, because a String body could be anything; the helper adds it.

3. Listing, with a query parameter

function list_notes(req)
    params = queryparams(something(query(uri(req)), ""))
    q = lowercase(get(params, "q", ""))
    notes = lock(NOTES_LOCK) do
        sort!([n for n in values(NOTES) if occursin(q, lowercase(n.title))]; by = n -> n.id)
    end
    json(StatusCodes.OK, notes)
end

query(uri(req)) is the raw text after the ?, or nothing when there is no query. Facil does not parse or percent-decode it; URIs.queryparams does both and returns a Dict{String,String}.

Note the shape of the function: take the lock, copy out what you need, release it, and only then build the response. Hold a lock for as short a time as you can.

4. Creating, with validation

function create_note(req)
    data = try
        JSON.parse(body(req))
    catch
        return problem(StatusCodes.BAD_REQUEST, "the body is not valid JSON")
    end
    data isa AbstractDict || return problem(StatusCodes.BAD_REQUEST, "expected a JSON object")
    title = get(data, "title", nothing)
    title isa AbstractString && !isempty(title) ||
        return problem(StatusCodes.UNPROCESSABLE_ENTITY, "title is required")
    text = get(data, "text", "")
    text isa AbstractString || return problem(StatusCodes.UNPROCESSABLE_ENTITY, "text must be a string")
    note = lock(NOTES_LOCK) do
        id = NEXT_ID[]
        NEXT_ID[] += 1
        NOTES[id] = Note(id, title, text)
    end
    Response(StatusCodes.CREATED, JSON.json(note);
             headers = [header.CONTENT_TYPE => "application/json", header.LOCATION => "/notes/$(note.id)"])
end

body(req) is the request body as a String. The client can send anything, so each step that can fail returns an error response early:

  • 400 Bad Request when the body is not JSON at all;
  • 422 Unprocessable Entity when it is JSON but a field is missing or has the wrong type.

Without the try, bad JSON would throw inside the handler and the client would get a 500, which wrongly says the server is at fault.

A successful create answers 201 Created with a location header that points to the new note.

5. One note: path parameters

function get_note(id)
    note = lock(() -> get(NOTES, id, nothing), NOTES_LOCK)
    note === nothing ? problem(StatusCodes.NOT_FOUND, "no note $id") : json(StatusCodes.OK, note)
end

function delete_note(id)
    found = lock(() -> pop!(NOTES, id, nothing), NOTES_LOCK)
    found === nothing ? problem(StatusCodes.NOT_FOUND, "no note $id") : Response(StatusCodes.NO_CONTENT)
end

These take the note id as an argument. The router extracts it from the path.

6. Routing

Facil has no router. A handler looks at the method and the path and decides:

not_allowed(allow) = Response(StatusCodes.METHOD_NOT_ALLOWED, JSON.json((error = "method not allowed",));
                              headers = [header.CONTENT_TYPE => "application/json", header.ALLOW => allow])

function app(req)
    m, p = method(req), path(uri(req))
    if p == "/notes"
        m == Methods.GET && return list_notes(req)
        m == Methods.POST && return create_note(req)
        return not_allowed("GET, POST")
    end
    found = match(r"^/notes/(\d+)$", p)
    if found !== nothing
        id = parse(Int, found[1])
        m == Methods.GET && return get_note(id)
        m == Methods.DELETE && return delete_note(id)
        return not_allowed("GET, DELETE")
    end
    p == "/health" && return Response(StatusCodes.OK, "ok")
    problem(StatusCodes.NOT_FOUND, "no such route")
end
  • method(req) compares with the constants in Methods.
  • path(uri(req)) is the path without the query string.
  • A regular expression captures the path parameter. \d+ only matches digits, so parse(Int, ...) cannot fail.
  • A known path with the wrong method gets 405 Method Not Allowed and an allow header, which is what HTTP asks for. An unknown path gets 404.

For larger applications, Routing shows a small table-driven router you can copy.

7. Serving

if abspath(PROGRAM_FILE) == @__FILE__
    serve(app, "127.0.0.1", 8080; max_body_size = 64 * 1024)
end

max_body_size caps request bodies at 64 KiB; a larger one gets 413 Payload Too Large before your handler runs. A notes API has no reason to accept the default 50 MiB.

The if makes the file do two jobs: run as a program (julia notes.jl serves), and be included by a test without starting a server.

8. Run it

julia -t 4 --project=. notes.jl

In another terminal:

$ curl -i -X POST http://127.0.0.1:8080/notes -d '{"title": "Buy milk", "text": "2 litres"}'
HTTP/1.1 201 Created
content-type: application/json
location: /notes/1
content-length: 45

{"id":1,"title":"Buy milk","text":"2 litres"}

$ curl 'http://127.0.0.1:8080/notes?q=MILK'
[{"id":1,"title":"Buy milk","text":"2 litres"}]

$ curl -X POST http://127.0.0.1:8080/notes -d '{"text": "x"}'
{"error":"title is required"}

$ curl http://127.0.0.1:8080/notes/7
{"error":"no note 7"}

$ curl -i -X PUT http://127.0.0.1:8080/notes/1
HTTP/1.1 405 Method Not Allowed
allow: GET, DELETE
...

$ curl -X DELETE -i http://127.0.0.1:8080/notes/1
HTTP/1.1 204 No Content

(The -i output is shortened here: Facil also sends connection, date and last-modified headers.)

The first request after start-up takes a few hundred milliseconds while Julia compiles your handler; later ones take microseconds. Deployment shows how to remove that delay.

9. Test it

Save this as test_notes.jl next to notes.jl:

using Test, Facil, JSON
import Downloads

include(joinpath(@__DIR__, "tutorial_notes.jl"))

function call(server, method, target; body = nothing)
    out = IOBuffer()
    r = Downloads.request("http://127.0.0.1:$(port(server))$target"; method, output = out,
                          input = body === nothing ? nothing : IOBuffer(body), throw = false)
    (status = r.status, headers = Dict(r.headers), body = String(take!(out)))
end

@testset "notes API" begin
    server = serve!(app, 0)
    try
        r = call(server, "POST", "/notes"; body = """{"title": "Milk", "text": "2 litres"}""")
        @test r.status == 201
        @test r.headers["location"] == "/notes/1"
        @test JSON.parse(r.body)["title"] == "Milk"

        @test call(server, "POST", "/notes"; body = "{oops").status == 400
        @test call(server, "POST", "/notes"; body = """{"text": "no title"}""").status == 422

        r = call(server, "GET", "/notes?q=mi")
        @test r.status == 200
        @test length(JSON.parse(r.body)) == 1
        @test isempty(JSON.parse(call(server, "GET", "/notes?q=bread").body))

        @test call(server, "GET", "/notes/1").status == 200
        @test call(server, "GET", "/notes/99").status == 404
        @test call(server, "PUT", "/notes/1").headers["allow"] == "GET, DELETE"
        @test call(server, "DELETE", "/notes/1").status == 204
        @test call(server, "GET", "/notes/1").status == 404
    finally
        close(server)
    end
end
$ julia -t 4 --project=. test_notes.jl
Test Summary: | Pass  Total  Time
notes API     |   13     13  0.7s

The pattern is the same for any Facil application:

  • serve!(app, 0) starts the real server on a free port, and port(server) tells you which. Never hard-code a port in a test.
  • A real HTTP client makes the requests. Downloads ships with Julia, so the test needs no extra dependency. Write import Downloads, not using Downloads: Downloads exports a Response type of its own, which would clash with Facil's.
  • close(server) in a finally block stops the server even when a test fails.

Testing has more, including calling handlers directly without a server.

Where to go from here

You now have every piece of a typical JSON service. To take it to production:

  • Deployment: threads, a systemd unit, a container image, a reverse proxy, health checks, faster start-up.
  • Shutdown and signals: finish requests in flight when the process is told to stop.
  • Security: limits, timeouts and HTTPS.
  • Errors and logging: an access log and your own error pages.
