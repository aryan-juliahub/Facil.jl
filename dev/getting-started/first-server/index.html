Your first server

This page explains the model behind every Facil program: a request comes in, your handler is called with it, and what the handler returns is sent back. Read it once and the rest of the documentation will make sense.

Five lines

using Facil

serve("127.0.0.1", 8080) do req
    Response(StatusCodes.OK, "hello")
end
  • using Facil brings in the server and the HTTP types. You do not need any other package.
  • serve starts listening on 127.0.0.1:8080 and blocks until the server is stopped.
  • The do req ... end block is the handler. Facil calls it once for every request, with a Request.
  • The handler returns a Response: a status and a body.

serve(handler, host, port) is the same call written without do. Any callable works as a handler: an anonymous function, a named function, or a callable object.

The request → handler → response model

  1. facil.io accepts the connection and parses the request head on its event-loop thread, the reactor. A request that is malformed or over a limit is answered there (400, 408, 431) and never reaches your code.
  2. The body is read. By default the whole body is collected in memory. The before_body option can stream it, spool it to disk or reject it; see Request bodies and uploads.
  3. Your handler is called with a Request{String}. By default it runs on a worker task, on one of Julia's threads, so it may take its time: query a database, read a file, sleep. With inline = true it runs on the reactor thread itself, which is faster for handlers that never wait. Handlers and concurrency explains the choice.
  4. The return value is written back, and the connection waits for the client's next request.

There is no middleware stack, router or context object in between. A handler is a function from a request to a response, which makes it easy to test: call it. See Testing.

What a handler receives

The request is an HttpTypes Request. You read it with accessor functions:

using Facil

serve("127.0.0.1", 8080) do req
    lines = [
        "method: $(method(req))",
        "path:   $(path(uri(req)))",
        "query:  $(something(query(uri(req)), "(none)"))",
        "agent:  $(get(headers(req), "user-agent", "(none)"))",
        "body:   $(sizeof(body(req))) bytes",
    ]
    Response(StatusCodes.OK, join(lines, "\n") * "\n"; headers = ["x-served-by" => "facil"])
end
$ curl -X POST 'http://127.0.0.1:8080/orders/17?expand=items' -d '{"qty": 2}'
method: POST
path:   /orders/17
query:  expand=items
agent:  curl/8.7.1
body:   10 bytes
AccessorGivesType
method(req)the request method; compare with Methods.GET, Methods.POST, ...HttpMethod
uri(req)the request targetUri
path(uri(req))the path, as sent (not percent-decoded)String
query(uri(req))the query string after ?, or nothingString or nothing
headers(req)the headers; names are case-insensitiveHeaderMap
body(req)the body; "" when there is noneString
version(req)Versions.HTTP_11 or Versions.HTTP_10Version

What a handler returns

using Facil

function app(req)
    p = path(uri(req))
    if p == "/text"
        "a String is sent as 200 text/plain"
    elseif p == "/json"
        Response(StatusCodes.OK, """{"ok":true}"""; headers = [header.CONTENT_TYPE => "application/json"])
    elseif p == "/bytes"
        Response(StatusCodes.OK, UInt8[0x89, 0x50, 0x4e, 0x47])
    elseif p == "/created"
        Response(201, "made"; headers = [header.LOCATION => "/things/1"])
    elseif p == "/empty"
        Response(StatusCodes.NO_CONTENT)
    elseif p == "/boom"
        error("this handler has a bug")
    else
        Response(StatusCodes.NOT_FOUND, "no such page\n")
    end
end

serve(app, "127.0.0.1", 8080)
  • A Response: Response(status, body; headers = [...]). The status is a constant from StatusCodes or an integer. The body is a String, a Vector{UInt8} or nothing.
  • A String, as a shortcut for 200 with text/plain; charset=utf-8.
  • Something special: stream for a body produced over time, sse for server-sent events, sendfile for a file, websocket to accept a WebSocket.

Facil sets content-length for you, and adds a content-type when a non-empty body has none: text/plain; charset=utf-8 for a String, application/octet-stream for bytes.

If the handler throws (/boom above), the client gets 500 Internal Server Error, the error and its stack trace are printed to stderr, and the server carries on. See Errors and logging.

`Response(404)` is an error

A single integer argument is ambiguous between a status and a body, so Response(404) throws an ArgumentError. Write Response(StatusCodes.NOT_FOUND) for a response without a body, or give both: Response(404, "not found").

Sending responses covers statuses, headers and bodies.

serve and serve!

serve blocks, which is what the last line of a server program wants. serve! takes the same arguments and returns a Server immediately. Use it at the REPL, in tests, and when one process runs several servers:

julia> using Facil
julia> server = serve!(req -> Response(StatusCodes.OK, "hello"), "127.0.0.1", 0)Facil.Server("127.0.0.1", 44987, open)
julia> port(server)   # port 0 asked for any free port; this is the one it got44987
julia> isopen(server)true
julia> close(server)

Both accept keywords that set limits, timeouts, HTTPS, compression and more. They are all listed in Configuration.
