Requests and responses

This page documents Request and Response, the two message types, their accessors, and the body-less heads RequestParts and ResponseParts. A Facil handler receives a Request{String} and returns a Response; use this page to see every way to read the one and build the other.

Reading a request

A request has six parts, each with an accessor of the same name as its field:

julia> using HttpTypes
julia> req = Request(; method = "POST", uri = "/users?page=2",
                     headers = ["Content-Type" => "application/json"], body = "{\"name\":\"ada\"}");
julia> method(req)Methods.POST
julia> uri(req)uri"/users?page=2"
julia> version(req)Versions.HTTP_11
julia> headers(req)HeaderMap(hn"content-type" => hv"application/json")
julia> body(req)"{\"name\":\"ada\"}"
julia> extensions(req)Extensions()

The type parameter is the type of the body: this one is a Request{String}. The pages on methods, URIs, headers and extensions cover what you can do with each part.

Building a response

The usual form is a status and a body, with headers as a keyword:

julia> Response(StatusCodes.OK, "hello")Response{String}(status=StatusCodes.OK, version=Versions.HTTP_11, headers=HeaderMap(), body="hello")
julia> Response(StatusCodes.CREATED, "{}"; headers = [header.CONTENT_TYPE => "application/json",
                                                       header.LOCATION => "/users/7"])Response{String}(status=StatusCodes.CREATED, version=Versions.HTTP_11, headers=HeaderMap(hn"content-type" => hv"application/json", hn"location" => hv"/users/7"), body="{}")

A response without a body takes the status alone, and a body alone gets status 200:

julia> Response(StatusCodes.NO_CONTENT)Response{Nothing}(status=StatusCodes.NO_CONTENT, version=Versions.HTTP_11, headers=HeaderMap(), body=nothing)
julia> Response("hello")Response{String}(status=StatusCodes.OK, version=Versions.HTTP_11, headers=HeaderMap(), body="hello")

The status may be an integer when a body follows it. A single integer argument is refused, because it could be either a status or a body:

julia> status(Response(404, "not found"))StatusCodes.NOT_FOUND
julia> try
           Response(404)
       catch e
           sprint(showerror, e)
       end"ArgumentError: Response(::Integer) is ambiguous; write Response(StatusCode(404)) or Response(StatusCode(404), body)"
CallStatusBody
Response(StatusCodes.NOT_FOUND)404nothing
Response(StatusCode(404))404nothing
Response(404, "not found")404"not found"
Response(StatusCodes.NOT_FOUND, "not found")404"not found"
Response(; status = 404)404nothing

Changing a message

Messages are mutable. Assign a field to replace it (the value is converted and validated), and change headers and extensions in place:

julia> res = Response(StatusCodes.OK, "hello");
julia> res.status = 404;
julia> res.body = "gone";
julia> headers(res)[header.CACHE_CONTROL] = "no-store";
julia> resResponse{String}(status=StatusCodes.NOT_FOUND, version=Versions.HTTP_11, headers=HeaderMap(hn"cache-control" => hv"no-store"), body="gone")

map builds a message with a transformed body, and parts splits the head from the body so that it can be reused with another one:

julia> body(map(uppercase, res))"GONE"
julia> head = parts(res)ResponseParts(status=StatusCodes.NOT_FOUND, version=Versions.HTTP_11, headers=HeaderMap(hn"cache-control" => hv"no-store"))
julia> Response(head, codeunits("bytes")) isa Response{<:AbstractVector{UInt8}}true

map and parts share the headers and extensions of the original instead of copying them.

HttpTypes.Request — Type
Request(; method = Methods.GET, uri = uri"/", version = Versions.HTTP_11,
          headers = HeaderMap(), extensions = Extensions(), body = nothing)
Request(method, uri, body = nothing; version, headers, extensions)
Request(body)
Request(parts::RequestParts, body)
Request{T}(; method, uri, version, headers, extensions, body)
Request(method::HttpMethod, uri::Uri, version::Version, headers::HeaderMap{HeaderValue}, extensions::Extensions, body)

An HTTP request: a method, a target URI, a protocol version, headers, extensions and a body of type T.

Arguments

  • method: an HttpMethod, or a string or bytes to parse as one.
  • uri: a Uri, or a string or bytes to parse as one.
  • version: a Version.
  • headers: a HeaderMap (used as is, not copied) or any iterable of name => value pairs, added in order with repeated names kept.
  • extensions: an Extensions (used as is) or a tuple of values to insert.
  • body: any value; its type is the request's type parameter T. With Request{T}(; ...) and no body, the body is "" for String, nothing for Nothing, zero(T) for numbers and T() otherwise.

Request(body) takes every default (the crate's Request::new). The last, all-positional form takes values of exactly the field types, converts nothing, and is the cheapest.

Throws

  • InvalidMethod, InvalidUri, InvalidHeaderName, InvalidHeaderValue, MaxSizeReached when an argument does not convert.
  • MethodError for a version that is not a Version.

Reading and changing

  • Read with the accessors method, uri, version, headers, extensions, body, or the fields of the same names (r.method).
  • Assign a field to replace it: r.method = "PUT", r.uri = "/new", r.body = .... The value is converted like the constructor argument (the body to T), and throws the same errors.
  • Change headers and extensions in place: headers(r)["accept"] = "*/*".
  • map(f, r) returns a request with body f(body(r)); it shares the headers and extensions of r.
  • parts(r) is the request without its body.

show prints the method, URI, version, headers and body, but not the extensions.

Examples

julia> req = Request(; method = "POST", uri = "/users?page=2",
                     headers = ["Content-Type" => "application/json"], body = "{}")
Request{String}(method=Methods.POST, uri=uri"/users?page=2", version=Versions.HTTP_11, headers=HeaderMap(hn"content-type" => hv"application/json"), body="{}")

julia> method(req), path(uri(req)), body(req)
(Methods.POST, "/users", "{}")

julia> headers(req)[header.CONTENT_TYPE]
hv"application/json"

julia> req.method = "PUT"; append!(headers(req), "x-trace", "abc");

julia> method(req), length(headers(req))
(Methods.PUT, 2)

julia> body(map(length, req))
2

julia> Request(Methods.GET, "/health")
Request{Nothing}(method=Methods.GET, uri=uri"/health", version=Versions.HTTP_11, headers=HeaderMap(), body=nothing)

HttpTypes.Response — Type
Response(; status = StatusCodes.OK, version = Versions.HTTP_11,
           headers = HeaderMap(), extensions = Extensions(), body = nothing)
Response(status, body; version, headers, extensions)
Response(status::StatusCode; version, headers, extensions)
Response(body)
Response(parts::ResponseParts, body)
Response{T}(; status, version, headers, extensions, body)
Response(status::StatusCode, version::Version, headers::HeaderMap{HeaderValue}, extensions::Extensions, body)

An HTTP response: a status code, a protocol version, headers, extensions and a body of type T.

Arguments

  • status: a StatusCode, an integer in 100:999, or a string of three digits.
  • version: a Version.
  • headers: a HeaderMap (used as is, not copied) or any iterable of name => value pairs.
  • extensions: an Extensions (used as is) or a tuple of values to insert.
  • body: any value; its type is the response's type parameter T. Defaults as for Request.

One positional argument

  • Response(s::StatusCode) has status s and body nothing.
  • Response(body) has status 200 and that body (the crate's Response::new).
  • Response(404) throws an ArgumentError, because a bare integer could mean either. Write Response(StatusCodes.NOT_FOUND) or Response(StatusCode(404)) for an empty 404, and Response(404, "not found") for one with a body: with two positional arguments an integer status is accepted.

The last, all-positional form converts nothing and is the cheapest.

Throws

  • InvalidStatusCode, InvalidHeaderName, InvalidHeaderValue, MaxSizeReached when an argument does not convert.
  • ArgumentError for Response(::Integer).

Reading and changing

  • Read with status, version, headers, extensions, body, or the fields of the same names.
  • Assign a field to replace it: r.status = 404, r.body = ... (converted to T). Change headers and extensions in place.
  • map(f, r) returns a response with body f(body(r)), sharing the headers and extensions of r.
  • parts(r) is the response without its body.

show prints the status, version, headers and body, but not the extensions.

Examples

julia> res = Response(StatusCodes.CREATED, "ok"; headers = [header.LOCATION => "/users/7"])
Response{String}(status=StatusCodes.CREATED, version=Versions.HTTP_11, headers=HeaderMap(hn"location" => hv"/users/7"), body="ok")

julia> status(res), string(status(res)), body(res)
(StatusCodes.CREATED, "201 Created", "ok")

julia> Response(StatusCodes.NOT_FOUND)
Response{Nothing}(status=StatusCodes.NOT_FOUND, version=Versions.HTTP_11, headers=HeaderMap(), body=nothing)

julia> status(Response(404, "not found"))
StatusCodes.NOT_FOUND

julia> Response(404)
ERROR: ArgumentError: Response(::Integer) is ambiguous; write Response(StatusCode(404)) or Response(StatusCode(404), body)
[...]

julia> res.status = 200; status(res)
StatusCodes.OK

HttpTypes.parts — Function
parts(r::Request) -> RequestParts
parts(r::Response) -> ResponseParts

The head of a request or response, without its body.

The result shares its headers and extensions with r: changing them through either changes both. The other fields are copies, so assigning parts(r).method = ... does not change r. Request(parts, body) and Response(parts, body) build a message from a head and a body.

Examples

julia> res = Response(StatusCodes.OK, "hello"; headers = ["content-type" => "text/plain"]);

julia> p = parts(res)
ResponseParts(status=StatusCodes.OK, version=Versions.HTTP_11, headers=HeaderMap(hn"content-type" => hv"text/plain"))

julia> headers(p) === headers(res)
true

julia> body(Response(p, 5))
5
source
HttpTypes.RequestParts — Type
RequestParts(; method = Methods.GET, uri = uri"/", version = Versions.HTTP_11,
               headers = HeaderMap(), extensions = Extensions())

The head of a request, without a body (the crate's request::Parts).

It has the fields method, uri, version, headers and extensions, with the same conversions, accessors and assignment rules as Request. parts(req) takes the head off a request and Request(parts, body) puts a body on one; use the pair to swap a request's body for one of another type while keeping everything else.

Examples

julia> req = Request(; method = "POST", uri = "/upload", body = "raw text");

julia> p = parts(req)
RequestParts(method=Methods.POST, uri=uri"/upload", version=Versions.HTTP_11, headers=HeaderMap())

julia> body(Request(p, codeunits(body(req)))) isa AbstractVector{UInt8}
true
source
HttpTypes.ResponseParts — Type
ResponseParts(; status = StatusCodes.OK, version = Versions.HTTP_11,
                headers = HeaderMap(), extensions = Extensions())

The head of a response, without a body (the crate's response::Parts).

It has the fields status, version, headers and extensions, with the same conversions, accessors and assignment rules as Response. parts(res) takes the head off a response and Response(parts, body) puts a body on one.

Examples

julia> p = ResponseParts(; status = 302, headers = [header.LOCATION => "/login"])

julia> Response(p, "")
Response{String}(status=StatusCodes.FOUND, version=Versions.HTTP_11, headers=HeaderMap(hn"location" => hv"/login"), body="")
