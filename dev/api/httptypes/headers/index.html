Headers

This page documents the three header types: HeaderName, HeaderValue and the multimap HeaderMap that holds them. Use it to read request headers, set response headers, handle repeated headers such as Set-Cookie, and look up the constant for a standard header name.

Reading headers

headers(req) is a HeaderMap. Look a header up by constant or by string; strings match in any case:

julia> using HttpTypes
julia> req = Request(; uri = "/", headers = ["Content-Type" => "application/json",
                                             "Accept" => "text/html", "Accept" => "application/json"]);
julia> h = headers(req);
julia> h[header.CONTENT_TYPE]hv"application/json"
julia> h["content-type"] == "application/json"true
julia> get(h, "x-request-id", nothing)
julia> haskey(h, "ACCEPT")true

Indexing and get return the first value of a name. A header sent several times keeps all its values; get_all returns them:

julia> get_all(h, header.ACCEPT)2-element view(::Vector{HeaderValue}, 2:3) with eltype HeaderValue:
 hv"text/html"
 hv"application/json"
julia> length(h), keys_len(h)(3, 2)

A value is a HeaderValue, not a String. It compares with strings directly; convert it with as_str (or String) when you need string functions:

julia> v = h[header.CONTENT_TYPE]hv"application/json"
julia> v == "application/json"true
julia> startswith(as_str(v), "application/")true

Iterating a map yields name => value pairs, one per value:

julia> for (name, value) in h
           println(name, ": ", value)
       endcontent-type: application/json
accept: text/html
accept: application/json

Writing headers

Pass headers to a constructor as pairs, or change the map in place. h[name] = value replaces, append! adds:

julia> res = Response(StatusCodes.OK, "hi"; headers = [header.CONTENT_TYPE => "text/plain"]);
julia> h = headers(res);
julia> h[header.CACHE_CONTROL] = "no-store";
julia> append!(h, header.SET_COOKIE, "a=1");
julia> append!(h, header.SET_COOKIE, "b=2");
julia> hHeaderMap(hn"content-type" => hv"text/plain", hn"cache-control" => hv"no-store", hn"set-cookie" => hv"a=1", hn"set-cookie" => hv"b=2")
julia> delete!(h, header.CACHE_CONTROL);
julia> keys_len(h)2

Values convert from strings, integers and header names. Names and values are validated as they go in; a value with a line break can never get into a map:

julia> h["content-length"] = 2;
julia> h["vary"] = header.ACCEPT_ENCODING;
julia> tryparse(HeaderValue, "evil\r\nx-injected: 1") === nothingtrue

For a name that has no constant, write a literal with hn"...". It is checked when the code is parsed and costs nothing at run time; the same goes for hv"..." values:

julia> h[hn"x-request-id"] = hv"42";

To keep a secret out of logs, mark its value sensitive. show then hides it (but as_str and print do not):

julia> h[header.AUTHORIZATION] = set_sensitive(HeaderValue("Bearer abc123"), true);
julia> h[header.AUTHORIZATION]HeaderValue(<sensitive>)

Reference: header names

HttpTypes.HeaderName — Type
HeaderName(src)
HeaderName(ptr::Ptr{UInt8}, len::Integer)
tryparse(HeaderName, src)
parse(HeaderName, src)

A header field name, stored in lowercase.

Header names are case-insensitive in HTTP; a HeaderName folds uppercase ASCII letters when it is built, so two names that differ only in case are the same value. The 81 standard names are constants in header (header.CONTENT_TYPE, ...); parsing one of them returns that constant, and comparing two standard names compares one integer.

Arguments

  • src: an AbstractString or AbstractVector{UInt8}, or a HeaderName (returned as is).
  • ptr, len: a pointer to len bytes holding the name.

Returns

A HeaderName. tryparse returns nothing instead of throwing.

Throws

  • InvalidHeaderName if the source is empty, longer than 65,535 bytes, or holds a byte that is not a token character (space, :, control bytes and non-ASCII bytes are all rejected).

Notes

  • name == "Content-Type" compares with a string, ignoring ASCII case.
  • as_str, string(name), String(name) and print give the lowercase text; show prints the literal hn"content-type".
  • hash(name) differs from the hash of the equal string, so do not mix HeaderName and String keys in one Dict. A HeaderMap accepts both.
  • For a literal name, hn"..." validates when the code is parsed and costs nothing at run time.

Examples

julia> HeaderName("Content-Type")
hn"content-type"

julia> HeaderName("Content-Type") === header.CONTENT_TYPE
true

julia> name = HeaderName("X-Request-Id")
hn"x-request-id"

julia> name == "x-request-ID", string(name)
(true, "x-request-id")

See also from_lowercase, from_static.

source

Reference: header values

HttpTypes.HeaderValue — Type
HeaderValue(src)
HeaderValue(ptr::Ptr{UInt8}, len::Integer)
HeaderValue(n::Integer)
HeaderValue(name::HeaderName)
tryparse(HeaderValue, src)
parse(HeaderValue, src)

A header field value.

Arguments

  • src: the value.
    • An AbstractString must be visible ASCII (0x20:0x7e) or tab.
    • An AbstractVector{UInt8} (or ptr, len) may also hold the opaque bytes 0x80:0xff, so values in other encodings can be carried through.
    • A HeaderValue is returned as is.
  • n::Integer: formatted in decimal. Accepted types are Int16, UInt16, Int32, UInt32, Int64 and UInt64; other integer types are a MethodError.
  • name::HeaderName: the name's text becomes the value (useful for headers such as vary and access-control-allow-headers).

Returns

A HeaderValue. tryparse returns nothing instead of throwing. The empty string is a valid value.

Throws

  • InvalidHeaderValue for control bytes (including CR and LF) and DEL, and for non-ASCII bytes in a string source.

Notes

  • v == "text/plain" compares with a string and v == bytes with a byte vector. Values order (isless) by their bytes. hash(v) differs from the hash of the equal string.
  • as_str, String(v), string(v) and print give the bytes without checking them; to_str throws unless they are visible ASCII.
  • length(v) and sizeof(v) are the number of bytes; codeunits(v) views them.
  • show prints the literal hv"text/plain", a constructor call for values the literal cannot express, and HeaderValue(<sensitive>) for a value marked with set_sensitive.
  • convert(HeaderValue, x) accepts everything the constructor does, so header collections take plain strings and integers.

Examples

julia> HeaderValue("text/plain")
hv"text/plain"

julia> HeaderValue(1024)
hv"1024"

julia> HeaderValue(header.ACCEPT_ENCODING)
hv"accept-encoding"

julia> v = HeaderValue(UInt8[0x63, 0x61, 0x66, 0xe9]);

julia> length(v), tryparse(HeaderValue, "line\nbreak") === nothing
(4, true)

See also hv"...", is_sensitive.

HttpTypes.set_sensitive — Function
set_sensitive(v::HeaderValue, flag::Bool) -> HeaderValue

A copy of v with the sensitive mark set to flag. v itself is not changed (header values are immutable), so store the result.

The mark is a hint for whoever handles the value: show and repr print HeaderValue(<sensitive>) instead of the bytes, so the value stays out of logs that print a request, a response or a header map, and an HTTP/2 encoder should keep it out of its compression table.

Warning

Only show hides the bytes. print, string, String, as_str and to_str still return them. The mark does not take part in == or hash.

Examples

julia> token = set_sensitive(HeaderValue("Bearer abc123"), true)
HeaderValue(<sensitive>)

julia> HeaderMap(header.AUTHORIZATION => token)
HeaderMap(hn"authorization" => HeaderValue(<sensitive>))

julia> as_str(token)
"Bearer abc123"

HttpTypes.unchecked — Function
HttpTypes.unchecked(HeaderValue, ptr::Ptr{UInt8}, len::Integer) -> HeaderValue
HttpTypes.unchecked(HeaderValue, s::String) -> HeaderValue

A HeaderValue holding these bytes without validating them. Not exported.

For bytes that an HTTP parser has already checked. Passing bytes that HeaderValue(src) would reject (CR, LF, other control bytes) produces a value that can corrupt the message it is written into, so never use it on input that has not been validated. Reference: header map

HttpTypes.HeaderMap — Type
HeaderMap()
HeaderMap(pairs::Pair...)
HeaderMap(itr)
HeaderMap{T}()
HeaderMap{T}(capacity::Integer)
HeaderMap{T}(pairs::Pair...)
HeaderMap{T}(itr)

A multimap from HeaderName to values of type T: one name can hold several values, as HTTP headers do. HeaderMap() is HeaderMap{HeaderValue}(), the type Request and Response use.

Arguments

  • pairs, itr: name => value pairs to add, in order, as with extend!: a name given twice ends up with two values.
  • capacity::Integer: room to reserve for this many values.

Wherever a function takes a key it may be a HeaderName, a string in any case, or bytes; wherever it takes a value, anything that converts to T (for HeaderValue: strings, bytes, integers, header names).

Throws

  • InvalidHeaderName, InvalidHeaderValue for a pair that does not convert.
  • MaxSizeReached for a capacity over 24,576, or when the map would hold more than 24,576 distinct names.

Reading

CallResult
h[key]first value of key; KeyError if absent
get(h, key, default), get(f, h, key)first value, or default / f()
haskey(h, key)whether key has a value
get_all(h, key)view of every value of key
length(h)number of values, repeated names included
keys_len(h)number of distinct names
isempty(h)whether there are no values
keys(h), values(h)each distinct name once; every value
for (name, value) in hevery pair; eltype is Pair{HeaderName,T}

A lookup with a string that is not a valid header name finds nothing; it does not throw.

Writing

CallEffectReturns
h[key] = valueset key to the single value
insert!(h, key, value)the samefirst replaced value, or nothing
append!(h, key, value)add a value, keeping existing oneswhether key was present
extend!(h, itr)append many pairsh
remove!(h, key)remove every value of keyfirst value, or nothing
delete!(h, key)the sameh
pop!(h, key[, default])the samefirst value; KeyError or default if absent
drain!(h)remove everythingthe removed pairs
empty!(h)remove everythingh

Also copy(h) (the values themselves are shared), h1 == h2 (same names with the same values in the same order per name; the order of names does not matter), sizehint! and reserve!.

Order

Iteration yields names in the order they were first added, with all values of one name together, in the order they were added. Removing a name moves the last name into its place, so removal does not keep the order of the remaining names.

Examples

julia> h = HeaderMap("Content-Type" => "text/html", "Set-Cookie" => "a=1", "Set-Cookie" => "b=2")
HeaderMap(hn"content-type" => hv"text/html", hn"set-cookie" => hv"a=1", hn"set-cookie" => hv"b=2")

julia> h[header.CONTENT_TYPE]
hv"text/html"

julia> h["set-cookie"], length(get_all(h, "set-cookie"))
(hv"a=1", 2)

julia> length(h), keys_len(h)
(3, 2)

julia> h["x-request-id"] = "42";

julia> get(h, "x-missing", nothing) === nothing
true

julia> [as_str(name) for name in keys(h)]
3-element Vector{String}:
 "content-type"
 "set-cookie"
 "x-request-id"

Base.insert! — Method
insert!(h::HeaderMap, key, value)

Set key to the single value, replacing every value it had. The name keeps its position in the map; a new name goes at the end.

The first value that was replaced, or nothing if the key was absent. h[key] = value does the same and returns h.

HttpTypes.extend! — Function
extend!(h::HeaderMap, itr) -> h

Add every key => value pair of itr to the map.

Arguments

  • itr: an iterable of pairs (or 2-tuples). Each pair is added as with append!: values go after those the name already has.

When the element type of itr has keys typed Union{Nothing,HeaderName} (what drain! returns), the crate's extend rule applies instead: a pair with a name replaces the values of that name, and a pair whose key is nothing appends to the name before it.

Throws

  • InvalidHeaderName, InvalidHeaderValue, MaxSizeReached, as for append!. Pairs before the bad one have already been added.
  • ArgumentError if a drained sequence starts with a nothing key.

Examples

julia> h = HeaderMap("accept" => "text/html");

julia> extend!(h, ["accept" => "text/plain", "host" => "example.com"])
HeaderMap(hn"accept" => hv"text/html", hn"accept" => hv"text/plain", hn"host" => hv"example.com")

julia> other = HeaderMap("accept" => "*/*");

julia> extend!(other, drain!(h))
HeaderMap(hn"accept" => hv"text/html", hn"accept" => hv"text/plain", hn"host" => hv"example.com")

HttpTypes.remove! — Function
remove!(h::HeaderMap, key)
remove!(e::OccupiedEntry)
remove!(ext::Extensions, T::Type)

Remove something and return it, or nothing if it was not there.

  • remove!(h, key) removes every value of key from a HeaderMap and returns the first one. The last name in the map moves into the freed place. A key that is not a valid header name is simply absent.
  • remove!(e) removes the key of an OccupiedEntry and returns its first value.
  • remove!(ext, T) removes the value of type T from Extensions and returns it.

delete! does the same and returns the collection; pop! throws a KeyError when nothing was there.

Examples

julia> h = HeaderMap("accept" => "text/html", "accept" => "text/plain", "host" => "example.com");

julia> remove!(h, "Accept")
hv"text/html"

julia> h
HeaderMap(hn"host" => hv"example.com")

julia> remove!(h, "accept") === nothing
true

julia> ext = Extensions(); insert!(ext, 42);

julia> remove!(ext, Int), remove!(ext, Int)
(42, nothing)

Reference: entries

An entry is a handle on one key of a map, for "look up once, then read or write" code. Most programs only need or_insert!.

HttpTypes.entry — Function
entry(h::HeaderMap{T}, key) -> Union{OccupiedEntry{T},VacantEntry{T}}

Look key up once and return a handle for in-place work on it: an OccupiedEntry if the key has a value, a VacantEntry if not.

This is the way to "read, then insert or update" with a single lookup; or_insert! covers the common case.

Throws

  • InvalidHeaderName if key is not a valid name.

Examples

julia> h = HeaderMap("accept" => "*/*");

julia> entry(h, "accept") isa OccupiedEntry, entry(h, "host") isa VacantEntry
(true, true)

julia> or_insert!(entry(h, "host"), "example.com")
hv"example.com"

julia> or_insert!(entry(h, "host"), "other.example")
hv"example.com"

julia> h
HeaderMap(hn"accept" => hv"application/json", hn"accept" => hv"text/plain")
