HttpTypes

This is the reference for HttpTypes, the package that defines the values a Facil handler receives and returns: Request, Response, methods, status codes, headers and URIs. Use these pages to look up what a type accepts, what a function returns and what it throws.

HttpTypes is a pure-Julia port of the Rust http crate, version 1.5.0, with the crate's validation rules and its tests. It only describes HTTP messages; it does no I/O. It has no dependencies and runs on Linux, macOS and Windows.

Facil re-exports every name HttpTypes exports, so using Facil is enough. To use the types without a server, load the package on its own (it lives in lib/HttpTypes of the Facil repository):

using HttpTypes

A first look

julia> using HttpTypes
julia> req = Request(; method = "POST", uri = "/users?page=2",
                     headers = ["Content-Type" => "application/json"], body = "{\"name\":\"ada\"}")Request{String}(method=Methods.POST, uri=uri"/users?page=2", version=Versions.HTTP_11, headers=HeaderMap(hn"content-type" => hv"application/json"), body="{\"name\":\"ada\"}")
julia> method(req) == Methods.POSTtrue
julia> path(uri(req)), query(uri(req))("/users", "page=2")
julia> headers(req)[header.CONTENT_TYPE]hv"application/json"
julia> res = Response(StatusCodes.CREATED, "ok"; headers = [header.LOCATION => "/users/7"])Response{String}(status=StatusCodes.CREATED, version=Versions.HTTP_11, headers=HeaderMap(hn"location" => hv"/users/7"), body="ok")
julia> status(res), string(status(res))(StatusCodes.CREATED, "201 Created")

Conventions

These rules hold across the package.

Constructors validate and throw; tryparse returns nothing. Every type that can be built from text has both forms. The errors are all subtypes of HttpError.

julia> tryparse(HttpMethod, "G T")
julia> tryparse(Uri, "/has space")
julia> try
           HeaderName("bad name")
       catch e
           e
       endInvalidHeaderName()

Strings convert where a typed value is expected. Constructors, field assignment and HeaderMap functions take a String (or bytes) and parse it, so you rarely build the small types by hand.

julia> req.method = "PUT";
julia> req.uri = "/users/7";
julia> reqRequest{String}(method=Methods.PUT, uri=uri"/users/7", version=Versions.HTTP_11, headers=HeaderMap(hn"content-type" => hv"application/json"), body="{\"name\":\"ada\"}")

Constants live in namespaces. Methods.GET, StatusCodes.NOT_FOUND, Versions.HTTP_11, Schemes.HTTPS, header.CONTENT_TYPE. The namespaces are exported; the constants inside them are not.

show prints Julia, print prints HTTP. What the REPL displays can be pasted back as code; string and print give the text that goes on the wire.

julia> StatusCodes.NOT_FOUND, string(StatusCodes.NOT_FOUND)(StatusCodes.NOT_FOUND, "404 Not Found")
julia> header.CONTENT_TYPE, string(header.CONTENT_TYPE)(hn"content-type", "content-type")
julia> uri"/a?b", string(uri"/a?b")(uri"/a?b", "/a?b")

Literals are checked when the code is parsed. hn"...", hv"..." and uri"..." build a HeaderName, HeaderValue and Uri at macro expansion, so a typo fails before the program runs and the value costs nothing at run time.

Nothing is decoded. Paths and queries are kept as received: no percent-decoding, no splitting of query parameters, no path normalisation.

Text forms

as_str gives the wire text of any of the small types without allocating.

HttpTypes.as_str — Function
as_str(x) -> AbstractString

The text of x as it appears in an HTTP message, without allocating.

xResultExample
HttpMethodthe method token"GET"
StatusCodethe three digits"404"
Versionthe version string"HTTP/1.1"
HeaderNamethe lowercase name"content-type"
HeaderValuethe value's bytes, unchecked (see below)"text/plain"
Schemethe scheme as written"https"
Authoritythe authority as written"example.com:8080"
PathAndQuerypath and query; "/" when empty"/a?x=1"
Portthe port as written"+80"

Returns

A String for methods, status codes, versions, header names and header values; a SubString{String} (a view into the parsed text) for the URI components.

Notes

  • For a StatusCode, string(s) adds the reason phrase ("404 Not Found"); as_str(s) is the digits only.
  • For a HeaderValue, as_str does not check the bytes; to_str does.

Examples

julia> as_str(Methods.GET), as_str(StatusCodes.NOT_FOUND), as_str(Versions.HTTP_11)
("GET", "404", "HTTP/1.1")

julia> as_str(header.CONTENT_TYPE), as_str(hv"text/plain")
("content-type", "text/plain")

julia> as_str(Port("+80")), as_str(PathAndQuery("/a?x=1"))
("+80", "/a?x=1")
source
as_str(name::HeaderName)

The name as a lowercase String.

source
as_str(v::HeaderValue) -> String
String(v::HeaderValue) -> String

The value's bytes as a String, without checking them and without a copy.

A value built from bytes may hold opaque bytes (0x80:0xff), so the result is not always valid UTF-8. to_str is the checked form.

Examples

julia> as_str(hv"gzip, br")
"gzip, br"

julia> isvalid(as_str(HeaderValue(UInt8[0x63, 0x61, 0x66, 0xe9])))
false

All names

HttpTypes.HttpTypes — Module
HttpTypes

Common HTTP types: methods, status codes, protocol versions, header names and values, a header multimap, URIs, extensions, requests and responses. A pure-Julia port of the Rust http crate, version 1.5.0, with the crate's validation rules.

The package only describes HTTP messages; it does no I/O. Values are validated when they are built, so a Request or Response you hold is always well formed.

  • HttpMethod and Methods, StatusCode and StatusCodes, Version and Versions
  • HeaderName and header, HeaderValue, HeaderMap
  • Uri with Scheme, Authority, PathAndQuery, Port
  • Request, Response, Extensions
  • every error is an HttpError

Constructors throw on invalid input; tryparse(T, src) returns nothing instead. show prints Julia that reads back (Methods.GET, hn"accept", uri"/a"); print and string give the text that goes on the wire.

Examples

julia> req = Request(; method = "POST", uri = "/users?page=2", headers = ["Accept" => "*/*"], body = "{}");

julia> method(req), path(uri(req)), query(uri(req))
(Methods.POST, "/users", "page=2")

julia> headers(req)["accept"]
hv"*/*"

julia> string(status(Response(StatusCodes.NOT_FOUND)))
"404 Not Found"
