WebSockets and pub/sub

This page documents WebSocket connections and the process-local pub/sub that broadcasts to them. A handler accepts a WebSocket by returning websocket; from then on your callbacks receive a WebSocket. The WebSockets guide and the pub/sub guide have complete programs.

Accepting a connection

Facil.websocket — Function
websocket(req; on_open, on_message, on_close, on_ready, on_shutdown,
          max_message_size = 1 MiB, deflate = false, utf8_check = true,
          spawn = false, borrow = false, subprotocol = nothing) -> Facil.WebSocketUpgrade

Accept a WebSocket upgrade. Return the result from your handler.

Arguments

  • req: the upgrade request. If it is not a valid WebSocket upgrade the client gets a 400 and no callback runs; test with Facil.is_upgrade first to answer something else.

Callbacks

All are optional keywords.

  • on_open(ws): once, when the connection is ready and before any message.
  • on_message(ws, msg): for each message. msg is a String for a text message and a Vector{UInt8} for a binary one. Fragmented messages arrive whole.
  • on_close(ws): once, after the connection is gone. send no longer works.
  • on_ready(ws): when output that had been queued has all been sent; use it to resume producing after Facil.pending_bytes grew.
  • on_shutdown(ws): when the connection's server is closed or drained (close(server), SIGTERM under serve), or the process exits, while the connection is open, just before Facil sends a 1001 close. The last chance to send.

Keywords

  • spawn::Bool = false: where callbacks run.
    • false: on the reactor thread, in order. They must not block. An echo costs no task switch.
    • true: on Julia tasks, still one at a time and in order for each connection, so they may block. Reading from this client pauses while more than 16 MiB of its messages wait to be handled.
  • max_message_size::Integer = 1 MiB: a larger message closes the connection with code 1009.
  • utf8_check::Bool = true: a text message that is not valid UTF-8 closes the connection with code 1007. false skips the check.
  • deflate = false: true accepts the permessage-deflate extension (without context takeover) when the client offers it. An integer 1 to 9 does the same and sets the compression level, process-wide. Messages under 128 bytes, and those that do not shrink, are sent uncompressed.
  • borrow::Bool = false: with spawn = false, pass each binary message as a view of facil.io's buffer instead of a copy. The vector is valid only until on_message returns; copy it to keep it.
  • subprotocol::Union{Nothing,AbstractString} = nothing: sent back as Sec-WebSocket-Protocol. Choose it from the request's header of that name.

Returns

A Facil.WebSocketUpgrade for the handler to return.

Throws

  • ArgumentError if max_message_size is not positive, a deflate level is outside 1:9, or subprotocol contains a line break.

Notes

  • An exception in a callback is logged; the connection stays open.
  • Pings from the client are answered by facil.io, and an idle connection is pinged every 40 seconds. The server's timeout keyword does not change that.
  • To send one message to many clients, use subscribe and publish instead of a loop over send.

Examples

An echo server. A WebSocket needs a WebSocket client, so this example only builds the upgrade; docs/examples/ws_echo.jl is the complete program, which the documentation build runs against a client.

julia> using Facil

julia> function app(req)
           Facil.is_upgrade(req) || return Response(StatusCodes.UPGRADE_REQUIRED, "WebSocket only")
           websocket(req;
                     on_open = ws -> send(ws, "welcome"),
                     on_message = (ws, msg) -> send(ws, msg))
       end;

julia> req = Request(Methods.GET, "/"; headers = ["upgrade" => "websocket"]);

julia> app(req) isa Facil.WebSocketUpgrade
true

julia> status(app(Request(Methods.GET, "/")))
StatusCodes.UPGRADE_REQUIRED

See the WebSockets guide.

Facil.is_upgrade — Function
Facil.is_upgrade(req::Request) -> Bool

Whether req asks to switch to the WebSocket protocol (its upgrade header names websocket).

Use it to serve a normal response and a WebSocket on the same path, or to answer non-WebSocket requests with a helpful status instead of the 400 that returning websocket for them produces.

Using a connection

Facil.WebSocket — Type
WebSocket

One WebSocket connection. Facil creates it when a handler returns websocket and passes it to every callback.

CallEffect
send(ws, msg)send a text (String) or binary (Vector{UInt8}) message
close(ws; code, reason)start the closing handshake
isopen(ws)true between on_open and the close
subscribe(ws, channel)forward a pub/sub channel to this client
Facil.pending_bytes(ws)bytes queued for the client and not yet sent
ws.dataa field of type Any for your own per-connection state, initially nothing

send, close, subscribe and unsubscribe are safe from any task or thread, so you may keep a WebSocket (in a Dict, a Set behind a lock) and use it outside its callbacks. Drop it in on_close.

source
Sockets.send — Method
send(ws::WebSocket, msg) -> Bool

Send msg to the client as one WebSocket message.

Arguments

  • msg: a String (or any AbstractString) is sent as a text message, a Vector{UInt8} (or any byte vector) as a binary message.

Returns

true if the message was queued; false, sending nothing, if the connection is closing or closed. It does not throw for a closed connection.

Notes

  • Safe from any task or thread, inside or outside the callbacks.
  • It never blocks. Bytes the socket does not take at once are copied and queued, so a client that does not read makes memory grow: watch Facil.pending_bytes or on_ready when you send faster than clients may read.
  • A String is not checked for valid UTF-8.

See websocket for an example.

source
Base.close — Method
close(ws::WebSocket; code = 1000, reason = "")

Start the WebSocket closing handshake.

Keywords

  • code::Integer = 1000: the close code: 1000 (normal), 1001 to 1014, or an application code 3000 to 4999.
  • reason::AbstractString = "": text sent with it; truncated to 123 bytes.

Returns nothing at once. The socket closes when the client answers, or after 3 seconds. on_close runs after that. Safe from any thread; does nothing on a connection that is already closing.

Throws

  • ArgumentError for a code outside those ranges.
source
Facil.pending_bytes — Function
Facil.pending_bytes(ws::WebSocket) -> Int

The number of bytes queued for this client that the socket has not taken yet; 0 for a closed connection.

send never blocks, so this is how you see a client falling behind. A common pattern: stop producing when it passes a threshold and continue in on_ready.

Pub/sub

publish reaches two kinds of subscriber: WebSocket clients, which receive the message without any Julia code running, and Julia callbacks.

Facil.publish — Function
publish(channel, msg)

Send msg to every subscriber of channel in this process.

Arguments

  • channel::AbstractString: the channel name.
  • msg: a String or a byte vector. It is copied, so you may reuse the buffer.

Subscribers are the callbacks registered with subscribe(f, channel) and the WebSocket clients subscribed with subscribe(ws, channel).

Returns

nothing. Publishing to a channel nobody subscribes to is not an error.

Notes

  • Safe from any task or thread. Delivery happens later, on the reactor thread; publish does not wait for it.
  • Messages from one publishing thread are delivered in order.
  • Pub/sub is local to the process: nothing is sent to other processes or machines.

Examples

A handler that announces to every WebSocket client on the "chat" channel:

julia> using Facil

julia> import Downloads

julia> seen = Channel{String}(8);

julia> sub = subscribe(msg -> put!(seen, msg), "chat");

julia> server = serve!(0) do req
           publish("chat", body(req))
           Response(StatusCodes.NO_CONTENT)
       end;

julia> r = Downloads.request("http://127.0.0.1:$(port(server))/"; method = "POST", input = IOBuffer("deploy at 5"), output = devnull);

julia> r.status
204

julia> take!(seen)
"deploy at 5"

julia> unsubscribe(sub); close(server)

Facil.subscribe — Method
subscribe(ws::WebSocket, channel; binary = nothing) -> Bool

Forward every message published to channel to this WebSocket client.

No Julia code runs per message: facil.io builds the frame once and shares it among all subscribers of the channel, which is what makes broadcasting to thousands of clients cheap.

Arguments

  • channel::AbstractString: the channel name; any string.
  • binary = nothing: true sends binary messages, false text. By default a message is sent as text when it is valid UTF-8 and as binary otherwise.

Returns

true if subscribed, false if the connection is not open (before on_open or after the close).

Notes

  • Call it in on_open or later. Subscribing twice to one channel is a no-op.
  • The subscription ends with the connection or with unsubscribe.
  • A client that reads too slowly is handled by Facil.slow_subscribers!.

See publish and the pub/sub guide.

source
Facil.unsubscribe — Method
unsubscribe(ws::WebSocket, channel) -> Bool

Stop forwarding channel to this WebSocket client. Returns false if the connection is not open. Unsubscribing from a channel it is not subscribed to does nothing.

source
Facil.subscribe — Method
subscribe(f, channel; spawn = false) -> Facil.Subscription

Call f(msg::String) for every message published to channel in this process.

Arguments

  • f: the callback. It receives the message as a String (bytes published as a vector arrive as a String holding those bytes).
  • channel::AbstractString: the channel name; matched exactly.

Keywords

  • spawn::Bool = false: false runs f on the reactor thread, one message at a time in publishing order; f must not block. true runs each call on its own Julia task: f may block, but calls can overlap and order is not kept.

Returns

A Facil.Subscription; pass it to unsubscribe to stop.

Notes

  • Starts the reactor if no server has yet.
  • An exception in f is logged; the subscription stays active.
  • To deliver a channel to WebSocket clients use subscribe(ws, channel), which runs no Julia code per message.

Examples

julia> using Facil

julia> inbox = Channel{String}(8);

julia> sub = subscribe(msg -> put!(inbox, msg), "news");

julia> publish("news", "hello")

julia> take!(inbox)
"hello"

julia> unsubscribe(sub)

julia> isopen(sub)
false

Slow clients and settings

Facil.slow_subscribers! — Function
Facil.slow_subscribers!(; limit, policy = :close)

Decide what a broadcast does with a WebSocket subscriber that is not reading.

Keywords

  • limit::Integer: a subscriber with more than this many unsent bytes queued counts as slow. 0 disables the check (the default state): queues grow without bound.
  • policy::Symbol = :close: what happens to a slow subscriber when the next message is published:
    • :close: its connection is closed;
    • :drop_newest: the new message is skipped for it;
    • :drop_oldest: its oldest unsent broadcasts are discarded to make room;
    • :ignore: nothing; the event is only counted.

Throws

  • ArgumentError for a negative limit or an unknown policy.

Notes

Process-wide, for every channel and server. It applies to messages delivered through subscribe(ws, channel), not to send. Facil.slow_subscriber_stats counts what happened.

Examples

julia> using Facil

julia> Facil.slow_subscribers!(; limit = 4 * 1024 * 1024, policy = :drop_oldest)

julia> Facil.slow_subscribers!(; limit = 0)

Facil.websocket_compressor! — Function
Facil.websocket_compressor!(codec::Symbol)

Choose the codec used for WebSocket permessage-deflate, process-wide.

  • :zlibng (the default): zlib-ng compresses and libdeflate decompresses.
  • :zlib: facil.io's built-in codec, which uses the system zlib.

Call it before serving. Throws ArgumentError for any other symbol. It only matters for connections accepted with websocket(...; deflate = true).
