Request bodies

This page documents how a server receives request bodies. A handler gets a Request{String}, a type from HttpTypes; its accessors (method, uri, headers, body and the rest) are on the HttpTypes messages page. What is documented here is Facil's part: choosing, per request, where the body goes.

The before_body keyword of serve! is a function that receives a RequestHead and returns one of four values:

before_body returnsThe bodyThe handler reads it with
Buffer() (default)is read into memorybody(req), a String
Stream()is handed over as it arrivesbody_chunks or body_stream
Stream(on_chunk)is passed to on_chunk piece by piecenothing; on_chunk saw it
Spool()is written to a temporary filebody_stream, an IOStream
Reject(status)is not readthe handler is not called

The request bodies guide shows complete programs for each.

Choosing where a body goes

Facil.RequestHead — Type
RequestHead

What before_body receives: a request whose body has not been read yet.

Read it with the accessors of a request: method(head), uri(head), version(head) and headers(head).

Fields

  • head.content_length::Int: the declared content-length, or -1 when the body is chunked and its length is not known yet (Facil.ischunked(head)).

before_body is called only for requests that have a body. It runs on the reactor thread, so decide from the head alone and do not block.

Examples

julia> using Facil

julia> function choose(head::RequestHead)
           method(head) == Methods.PUT || return Reject(405)
           head.content_length > 1_000_000 && return Spool()
           Buffer()
       end;

julia> server = serve!(req -> "ok", 0; before_body = choose);

julia> close(server)
source
Facil.ischunked — Function
Facil.ischunked(head::RequestHead) -> Bool

Whether the request body is sent with transfer-encoding: chunked, so its length is not known when before_body runs (head.content_length == -1).

source
Facil.Buffer — Type
Buffer()

A before_body result: read the whole request body into memory before the handler is called. This is the default.

The handler gets the body as body(req), a String. body_stream gives an IOBuffer over the same bytes.

Limits

A body larger than the server's body_in_memory (default 16 MiB) gets a 413 and the handler is not called. For a body with a declared content-length the check happens before any of it is read; for a chunked body, once the limit is passed. max_body_size applies as well.

Examples

julia> using Facil

julia> import Downloads

julia> server = serve!(0; before_body = head -> Buffer()) do req
           Response(StatusCodes.OK, "got $(sizeof(body(req))) bytes")
       end;

julia> out = IOBuffer();

julia> Downloads.request("http://127.0.0.1:$(port(server))/"; method = "POST", input = IOBuffer("hello"), output = out);

julia> String(take!(out))
"got 5 bytes"

julia> close(server)

See also Stream, Spool, Reject and the request bodies guide.

source
Facil.Stream — Type
Stream(; on_chunk = nothing, high_water = 4 MiB)
Stream(on_chunk)

A before_body result: do not keep the request body; hand it over in pieces as it arrives.

Arguments

  • on_chunk = nothing: a function on_chunk(bytes::Vector{UInt8}), called on the reactor thread for each piece as it arrives. bytes is valid only during the call (copy it to keep it) and the function must not block. The handler runs once the body has ended; body(req) is "".
  • high_water::Integer = 4 MiB: without on_chunk, reading from the socket pauses while more than this many bytes are waiting to be read by a task handler, and resumes when half of them are consumed.

Reading the body without on_chunk

The handler reads the pieces from body_chunks(req) or the IO body_stream(req):

  • A task handler (inline = false) starts as soon as the request head has arrived and reads the body while the client is still sending it. Unread data beyond high_water holds the client back.
  • An inline handler runs once the whole body has been received and queued in memory, so Stream() saves nothing there; use on_chunk.

Notes

  • before_body makes a new Stream for each request, so per-request state can live in the on_chunk closure.
  • If on_chunk throws, the error is logged and the request gets a 500.
  • If the client disconnects mid-body, a read in a task handler throws Facil.BodyAborted.
  • Each chunk read by a task handler crosses from the reactor thread to the task. When the work per chunk does not block, on_chunk avoids that.

Examples

Count the bytes of an upload without keeping them:

julia> using Facil

julia> import Downloads

julia> server = serve!(0; before_body = head -> Stream()) do req
           n = 0
           for chunk in body_chunks(req)
               n += length(chunk)
           end
           Response(StatusCodes.OK, "streamed $n bytes")
       end;

julia> out = IOBuffer();

julia> Downloads.request("http://127.0.0.1:$(port(server))/"; method = "POST", input = IOBuffer("x"^100_000), output = out);

julia> String(take!(out))
"streamed 100000 bytes"

julia> close(server)

See also Buffer, Spool, BodyStream.

source
Facil.Spool — Type
Spool()

A before_body result: write the request body to a temporary file as it arrives, then call the handler.

The handler reads the file through body_stream(req), an IOStream positioned at the start; body(req) is "". The file is already unlinked, so it disappears when the stream is closed or collected, whatever happens to the process. It is created in tempdir().

Use it for uploads that are too large for memory and that the handler wants as a seekable file. max_body_size still applies; raise it for large uploads. If writing fails (a full disk), the error is logged and the request gets a 500.

Examples

julia> using Facil

julia> import Downloads

julia> server = serve!(0; before_body = head -> Spool()) do req
           io = body_stream(req)
           Response(StatusCodes.OK, "first line: " * readline(io))
       end;

julia> out = IOBuffer();

julia> Downloads.request("http://127.0.0.1:$(port(server))/"; method = "POST", input = IOBuffer("alpha\nbeta\n"), output = out);

julia> String(take!(out))
"first line: alpha"

julia> close(server)
source
Facil.Reject — Type
Reject(status::Integer = 413)

A before_body result: answer status at once, without reading the request body, and close the connection. The handler is not called.

Arguments

  • status: a 4xx or 5xx status code. The response body is the status text.

Throws

  • ArgumentError if status is outside 400:599.

Notes

A client that sent Expect: 100-continue gets the final status instead of 100 Continue, so it never sends the body. Other clients may see the connection close while they are still sending.

Examples

Refuse uploads from clients that did not authenticate, before reading them:

julia> using Facil

julia> import Downloads

julia> check(head) = haskey(headers(head), "authorization") ? Buffer() : Reject(401);

julia> server = serve!(req -> "stored", 0; before_body = check);

julia> r = Downloads.request("http://127.0.0.1:$(port(server))/"; method = "POST", input = IOBuffer("data"), output = devnull);

julia> r.status
401

julia> close(server)

Reading a body

Facil.body_stream — Function
body_stream(req::Request) -> IO

The request body as a readable IO, whatever before_body chose.

before_body resultbody_stream(req)
Buffer() (default)an IOBuffer over body(req)
Stream()a BodyStream that yields data as it arrives
Stream(on_chunk)an empty stream (on_chunk consumed the body)
Spool()an IOStream on the temporary file, at position 0

Each call returns the same stream for Stream and Spool, and a new IOBuffer for Buffer.

Examples

julia> using Facil

julia> req = Request(Methods.POST, "/upload", "line one\nline two\n");

julia> readline(body_stream(req))
"line one"
source
Facil.body_chunks — Function
body_chunks(req::Request)

An iterator over the request body in pieces, each a Vector{UInt8}, in the order they arrived.

With Stream() the pieces are what the socket delivered (no fixed size) and iterating blocks until the next one arrives; the loop ends when the body does. With other before_body results it iterates body_stream(req) in whatever pieces that stream has ready.

Throws

Facil.BodyAborted from the iteration if the client disconnects mid-body.

Examples

julia> using Facil

julia> req = Request(Methods.POST, "/upload", "hello");

julia> sum(length, body_chunks(req))
5
source
Facil.BodyStream — Type
BodyStream <: IO

A request body read while it arrives. body_stream(req) returns one when before_body chose Stream().

It is a read-only IO: read(io), read(io, n), read(io, UInt8), readbytes!, readavailable, readline, eof and bytesavailable work as on any stream. A read blocks the task until data arrives; eof(io) returns true once the client has sent the whole body. close(io) discards what is unread and lets the upload finish.

Throws

Reads throw Facil.BodyAborted if the client disconnects mid-body, and EOFError when asked for more bytes than the body has.

Notes

  • body_chunks(req) iterates the same data piece by piece without copying it into a buffer of your own.
  • When the handler returns, whatever it did not read is discarded.
  • Read it from one task at a time.
source
Facil.BodyAborted — Type
Facil.BodyAborted <: Exception

Thrown by a read from a BodyStream when the client's connection closed before the request body ended.

A task handler that lets it propagate is ended quietly: nothing is logged and no response is sent, since nobody is left to read it. Catch it to clean up a partial upload.

source

The client

Who sent a request, and whether it is still waiting for the answer. The Reading requests guide has a complete program.

Facil.client_address — Function
client_address(req::Request) -> Union{NamedTuple{(:ip, :port)},Nothing}

The address of the client that sent req: (ip = "203.0.113.7", port = 51234).

ip is the textual IPv4 or IPv6 address ("::1", or "::ffff:127.0.0.1" for an IPv4 client of a server listening on "::"), port the client's TCP port. It is the peer of the TCP connection, so behind a proxy it is the proxy's address; read forwarded or x-forwarded-for for the original client, if you trust the proxy.

Works for HTTP and HTTPS, in inline and task handlers, and in handlers that answer with websocket, sse or stream.

Returns

nothing when Facil has no connection for req: a request built by hand, or one whose inline handler returned a plain response without asking (task handlers, and inline handlers that answer with a stream, an event stream or a WebSocket, have it captured; another inline handler that keeps the request asks once while it runs).

Examples

julia> using Facil

julia> import Downloads

julia> server = serve!(0) do req
           c = client_address(req)
           c.ip
       end;

julia> String(take!(Downloads.download("http://127.0.0.1:$(port(server))/", IOBuffer())))
"127.0.0.1"

julia> close(server)

julia> client_address(Request(Methods.GET, "/")) === nothing
true

See also client_certificate.

source
Facil.client_certificate — Function
client_certificate(req::Request) -> Union{String,Nothing}

The certificate the client presented over mutual TLS, as PEM text (-----BEGIN CERTIFICATE----- ...), or nothing.

A client only sends a certificate when the server asks for one, which a TLSConfig with client_ca does. The handshake has already checked it against client_ca, so a certificate returned here is one those CAs issued. With require_client_cert = false a client may connect without one; nothing then.

Returns

nothing for plain HTTP, for a TLS client without a certificate, and in the cases where client_address is nothing.

Examples

serve!(8443; tls = TLSConfig(cert = "server.pem", key = "server.key",
                             client_ca = "clients-ca.pem")) do req
    pem = client_certificate(req)
    pem === nothing ? Response(StatusCodes.UNAUTHORIZED) : "hello, client"
end

Facil.isconnected — Function
isconnected(req::Request) -> Bool

Whether the client that sent req still has its connection open, as far as Facil can tell. For a task handler doing long work, to stop early when nobody waits for the answer.

The first call starts watching the connection. The value turns false within about half a second of the client closing its connection or resetting it, while the handler runs.

What counts as gone

  • A reset, or a connection that the server closed (for example by close(server)).
  • A client that closed its connection. TCP cannot tell that apart from a client that only stopped sending (a half-close) and still reads the reply, so for an HTTP/1.1 request Facil sends one 100 Continue interim response, which every HTTP/1.1 client skips: a client that closed answers it with a reset, one that half-closed reads it and stays connected. HTTP/1.0 requests and upgrade requests (WebSocket) cannot be sent an interim response, so for them only a reset counts.

Returns

  • In a task handler, the state above. After the handler has returned it no longer changes.
  • true in an inline handler (inline = true, or Julia with one thread): the reactor runs it and cannot watch the connection meanwhile. Also true for a request Facil did not receive (built by hand, as in a unit test).

Examples

serve!(8080) do req
    for step in 1:100
        isconnected(req) || return Response(StatusCodes.SERVICE_UNAVAILABLE)
        do_work(step)
    end
    "done"
end

See also on_disconnect.

source
Facil.on_disconnect — Function
on_disconnect(f, req::Request)

Run f() once if the client of req goes away while its task handler runs.

f runs on a Julia task of its own (never on the reactor thread), so it may block; it typically notifies the handler, for example by closing a Channel or setting a flag the handler checks. What counts as going away is described under isconnected; f runs within about half a second of it.

Notes

  • f runs at most once. If the client is already gone, it is scheduled at once. If the handler returns first, it never runs.
  • Several callbacks may be registered; each runs once.
  • An error thrown by f is logged to stderr.
  • Inline handlers: does nothing, as the reactor that runs them cannot watch the connection meanwhile.
  • The response the handler returns is still sent whatever happened; to a client that is gone it is discarded.

Examples

serve!(8080) do req
    cancelled = Threads.Atomic{Bool}(false)
    on_disconnect(() -> cancelled[] = true, req)
    result = long_computation(; stop = () -> cancelled[])
    cancelled[] ? Response(StatusCodes.SERVICE_UNAVAILABLE) : result
end
