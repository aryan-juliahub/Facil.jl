Responses

This page documents the functions that build a response other than a plain Response: streamed bodies, event streams, files, and compression. A plain response is Response(status, body; headers), documented on the HttpTypes messages page; what Facil does with it is described under serve! and in the responses guide.

Response(StatusCodes.OK, "text")a response with that body
"text"200, text/plain; charset=utf-8

sse(f, req)an event stream fed by f
sendfile(path)a file, with caching and range support
websocket(req; ...)a WebSocket connection (WebSockets)

Streamed responses

Facil.stream — Function
stream(f, req; status = 200, headers = [], compress = :auto, level = 0,
       spawn = nothing, high_water = 1 MiB) -> Response

Answer with a body that f writes piece by piece while it is being sent.

Return the result from your handler. Facil sends the response head, then calls f(io) with a ResponseStream; the body ends when f returns.

Arguments

  • f: f(io::ResponseStream). Write with write, print or println; call flush(io) to push a piece out now.
  • req: the request being answered.

Keywords

  • status = 200: a StatusCode or an integer.
  • headers = []: name => value pairs or a HeaderMap. Without a content-type, application/octet-stream is sent.
  • compress = :auto: :gzip, :br or :zstd compresses the body and sets content-encoding; :auto follows the server's compress option and the request's Accept-Encoding; nothing never compresses.
  • level::Integer = 0: compression level; 0 is the encoding's default.
  • spawn::Union{Nothing,Bool} = nothing: where f runs. nothing follows the server: on a worker task when the server runs task handlers, on the reactor thread when it runs inline handlers. true or false overrides that. On the reactor thread f must not block.
  • high_water::Integer = 1 MiB: on a task, write blocks while more than this many bytes wait for the client.

Returns

A Response to return from the handler. Nothing is sent until then.

Throws

  • ArgumentError if high_water is not positive or compress is not a known encoding.
  • InvalidStatusCode for a status outside 100:999.

Notes

  • HTTP/1.1 clients get transfer-encoding: chunked and the connection stays usable for further requests. HTTP/1.0 clients get a body that ends when the connection closes.
  • A HEAD request gets the head only; f is not called.
  • If f throws, the error is logged and the connection is closed, so the client sees an incomplete body rather than a truncated one that looks whole. The status line has already been sent and cannot change.
  • When the client goes away, isopen(io) turns false and the next write throws Base.IOError; f is then ended without logging.
  • A gzip body that ends within its first 128 KiB with no flush is compressed in one pass by libdeflate; longer ones are streamed by zlib-ng.

Examples

julia> using Facil

julia> import Downloads

julia> server = serve!(0) do req
           stream(req; headers = [header.CONTENT_TYPE => "text/plain"]) do io
               for i in 1:3
                   println(io, "line ", i)
                   flush(io)
               end
           end
       end;

julia> print(String(take!(Downloads.download("http://127.0.0.1:$(port(server))/", IOBuffer()))))
line 1
line 2
line 3

julia> close(server)

See the streaming guide.

Facil.ResponseStream — Type
ResponseStream <: IO

The body of a streamed response. stream passes one to your function.

CallEffect
write(io, x)queue a String, Vector{UInt8} or byte; print(io, ...) and println work too
flush(io)send what is queued now
isopen(io)false once the client has gone or the stream is closed
close(io)end the body; done for you when your function returns

Behaviour

  • Writes are buffered: on a task they are sent when 64 KiB is queued, when the task next yields, or on flush. Call flush after each piece that the client should see at once.
  • Back-pressure: on a task, write blocks while more than the stream's high_water bytes wait for a slow client. On the reactor thread it never blocks, so check Facil.pending_bytes yourself or use a task.
  • A String or Vector{UInt8} over 4 KiB is sent without a copy. Do not change a vector after writing it.
  • The stream is write-only: isreadable(io) is false.
  • Write to it from one task at a time.

Throws

write throws Base.IOError once the client has disconnected. If your function lets it propagate, the stream is ended quietly.

source
Base.flush — Method
flush(io::ResponseStream)

Send everything written to io so far, instead of waiting for more.

Call it after each piece the client should see immediately (a progress line, a log line being tailed). When the response is compressed, flush also ends the current compressed block so the client can decode what it has; flushing often costs compression ratio. Does nothing once the stream is closed.

source
Base.close — Method
close(io::ResponseStream)

End the body of a streamed response.

Sends the terminating chunk; the connection then serves its next request (an HTTP/1.0 connection is closed instead, which is how its body ends). stream calls this when your function returns, so call it only to end the body before doing more work. Closing twice does nothing.

source
Facil.wait_drain — Function
Facil.wait_drain(io)

Block the calling task until the client has taken most of what was written to io (a ResponseStream or SSEStream): no more than a quarter of its high_water is still queued, or the client has gone.

write and write_event call this for you when the queue passes high_water. Call it yourself to wait before producing an expensive piece. Must not be called on the reactor thread.

Server-sent events

Facil.sse — Function
sse(f, req; headers = [], high_water = 1 MiB) -> Response

Answer req with an event stream (server-sent events, text/event-stream).

Return the result from your handler. Facil sends the response head, then calls f(s) with an SSEStream on a worker task. The connection stays open until f returns or the client goes away.

Arguments

  • f: f(s::SSEStream). It runs on a task whatever the server's inline setting, so it may block, sleep and wait.
  • req: the request being answered. Its Last-Event-ID header becomes last_event_id(s).

Keywords

  • headers = []: extra response headers, as name => value pairs or a HeaderMap (for example access-control-allow-origin).
  • high_water::Integer = 1 MiB: write_event blocks while more than this many bytes wait for the client.

Returns

A Response to return from the handler.

Throws

  • ArgumentError if high_water is not positive.

Notes

  • The connection belongs to the event stream from then on: it serves no further HTTP requests and is closed when f returns.
  • Facil does not check the request's Accept header. Decide in your handler which requests get an event stream, by path or by Accept: text/event-stream.
  • If f throws, the error is logged and the stream is closed.
  • The response is never compressed.
  • A stream that sends nothing for longer than a proxy's idle timeout gets cut off; send Facil.write_comment every 15 to 30 seconds.

Examples

julia> using Facil

julia> import Downloads

julia> server = serve!(0) do req
           sse(req) do s
               for n in 1:3
                   write_event(s; data = "tick $n", id = n)
                   Facil.sleep(0.01)
               end
           end
       end;

julia> print(String(take!(Downloads.download("http://127.0.0.1:$(port(server))/", IOBuffer()))))
id: 1
data: tick 1

id: 2
data: tick 2

id: 3
data: tick 3

julia> close(server)

See the server-sent events guide.

Facil.SSEStream — Type
SSEStream

An open event stream. sse passes one to your function.

CallEffect
write_event(s; data, event, id, retry)send one event
Facil.write_comment(s, text)send a comment line (a keep-alive)
last_event_id(s)the Last-Event-ID the client reconnected with, or nothing
isopen(s)false once the client has gone or the stream is closed
wait(s)block until the client has gone or the stream is closed
close(s)close the connection; done for you when your function returns

write_event, Facil.write_comment and close may be called from any task or thread, so another part of your program can keep the SSEStream and push events to it while your function waits in wait(s).

Facil.write_event — Function
write_event(s::SSEStream; data = nothing, event = nothing, id = nothing, retry = nothing) -> Bool
write_event(s::SSEStream, data) -> Bool

Send one event on an event stream.

Arguments

  • data: the payload. Anything string accepts, or a byte vector holding UTF-8. Line breaks are allowed: each line becomes its own data: line and the client joins them with \n.
  • event: the event type, for addEventListener(type, ...) in a browser. Without it the client fires message.
  • id: the event id. The client sends the last one back as Last-Event-ID when it reconnects; see last_event_id.
  • retry::Integer: how many milliseconds the client should wait before reconnecting.

Returns

true if the event was queued, false if the client has gone or the stream is closed (nothing is sent then, and nothing is thrown).

Throws

  • ArgumentError if all four are nothing, or if event or id contains a line break.

Notes

Called on a task, it blocks while more than the stream's high_water bytes wait for a slow client. It may be called from any thread.

Examples

julia> using Facil

julia> import Downloads

julia> server = serve!(0) do req
           sse(req) do s
               write_event(s; event = "price", data = "42.10", id = 7)
               write_event(s, "two\nlines")
           end
       end;

julia> print(String(take!(Downloads.download("http://127.0.0.1:$(port(server))/", IOBuffer()))))
event: price
id: 7
data: 42.10

data: two
data: lines

julia> close(server)

Facil.write_comment — Function
Facil.write_comment(s::SSEStream, text = "") -> Bool

Send a comment line (: text) on an event stream. Clients ignore comments, so this is the usual keep-alive for streams that are quiet for long stretches: proxies and load balancers close connections that carry no bytes.

Returns true if it was queued, false if the client has gone. Throws ArgumentError if text contains a line break.

source
Facil.last_event_id — Function
last_event_id(s::SSEStream) -> Union{Nothing,String}

The value of the Last-Event-ID request header, or nothing if the client sent none.

A browser's EventSource reconnects by itself after a dropped connection and sends the id of the last event it received. Use it to resume where the client left off.

Examples

julia> using Facil

julia> import Downloads

julia> server = serve!(0) do req
           sse(req) do s
               write_event(s, "resuming after " * something(last_event_id(s), "nothing"))
           end
       end;

julia> url = "http://127.0.0.1:$(port(server))/";

julia> print(String(take!(Downloads.download(url, IOBuffer(); headers = ["Last-Event-ID" => "41"]))))
data: resuming after 41

julia> close(server)
source
Base.close — Method
close(s::SSEStream)

Close an event stream and its connection.

sse calls this when your function returns. Call it from elsewhere to end a stream whose function is blocked in wait(s). Closing twice does nothing. A browser EventSource treats the close as a dropped connection and reconnects; answer the reconnect with status 204 to make it stop.

Files

Facil.sendfile — Function
sendfile(path; status = 200, headers = []) -> Response
sendfile(req, path; status = 200, headers = []) -> Response

Answer with the contents of the file at path, sent by the kernel (sendfile(2)) without passing through Julia.

Return the result from your handler.

Arguments

  • path::AbstractString: the file to send. It is used as given: not URL-decoded, not checked against any root directory. Never build it from the request target without validating it yourself.
  • req: accepted and ignored, so sendfile(req, path) reads like the other response functions.

Keywords

  • status = 200: the status for a full response.
  • headers = []: extra headers, as name => value pairs or a HeaderMap. Headers the file sender sets itself win.

Returns

A Response to return from the handler. The file is opened when the response is sent, not when sendfile is called.

Throws

  • ArgumentError if path contains a NUL.

What the client gets

  • content-type from the extension (see Facil.mime_type), content-length, etag, last-modified and accept-ranges: bytes.
  • 304 Not Modified for a matching If-None-Match.
  • 206 Partial Content for a single-range Range request (honouring If-Range), 416 for a range outside the file.
  • The head only, for HEAD. An allow header for OPTIONS.
  • path * ".gz" instead, with content-encoding: gzip, when that file exists and the client accepts gzip.
  • 404 if the file does not exist; 405 with allow: GET, HEAD, OPTIONS for any other method.

Examples

julia> using Facil

julia> import Downloads

julia> dir = mktempdir(); write(joinpath(dir, "report.csv"), "a,b\n1,2\n");

julia> server = serve!(0) do req
           sendfile(joinpath(dir, "report.csv"); headers = ["content-disposition" => "attachment"])
       end;

julia> out = IOBuffer();

julia> r = Downloads.request("http://127.0.0.1:$(port(server))/"; output = out);

julia> String(take!(out))
"a,b\n1,2\n"

julia> Dict(r.headers)["content-type"]
"text/csv; charset=utf-8"

julia> close(server)

Facil.register_mime! — Function
Facil.register_mime!(ext, type)

Set the content-type sent for files whose name ends in .ext, by public_folder and sendfile.

Arguments

  • ext::AbstractString: the extension, with or without the leading dot; case is ignored. 1 to 15 bytes.
  • type::AbstractString: the full header value, for example "text/x-log; charset=utf-8".

Throws

  • ArgumentError for an empty or over-long extension, or a type containing a NUL or a line break.

Notes

The table is process-wide and shared by every server. Register before the first request for such a file. Registering an extension again replaces it.

Examples

julia> using Facil

julia> Facil.register_mime!(".log", "text/x-log; charset=utf-8")

julia> Facil.mime_type("server.log")
"text/x-log; charset=utf-8"

Compression

Facil.CompressOptions — Type
CompressOptions(; prefer = (:zstd, :br, :gzip), gzip = 6, br = 4, zstd = 3,
                min_size = 1024, compressible = Facil.compressible_type)

How a server compresses responses. Pass it as the compress keyword of serve!; compress = true is CompressOptions().

Keywords

  • prefer: the encodings the server offers, most wanted first, from :zstd, :br and :gzip. Among the encodings the client accepts with the highest q-value in Accept-Encoding, the one listed first here is used. Leave one out to never use it.
  • gzip::Integer = 6 (1 to 12), br::Integer = 4 (0 to 11), zstd::Integer = 3 (-7 to 22): the level for each encoding.
  • min_size::Integer = 1024: whole bodies smaller than this many bytes are sent as they are.
  • compressible = Facil.compressible_type: a function content_type::String -> Bool that says which content types to compress; see Facil.compressible_type.

Throws

  • ArgumentError for an unknown encoding in prefer, a level out of range or a negative min_size.

What is and is not compressed

A response is sent as it is when any of these holds: the client sent no Accept-Encoding or accepts none of prefer; the body is under min_size; the response already has a content-encoding; it has cache-control: no-transform; its status is 1xx, 204, 206 or 304; its content type is not compressible; or compressing did not make it smaller. sendfile responses and event streams are never compressed. A stream left at compress = :auto is compressed as it is written.

Whenever the content type is compressible Facil adds vary: accept-encoding, so caches keep the variants apart.

Compression runs where the handler runs: on a worker task, or on the reactor thread for an inline handler, where a large body delays other connections.

Examples

julia> using Facil

julia> import Downloads

julia> opts = CompressOptions(; prefer = (:gzip,), min_size = 100);

julia> server = serve!(req -> "hello "^1000, 0; compress = opts);

julia> r = Downloads.request("http://127.0.0.1:$(port(server))/"; output = devnull, headers = ["Accept-Encoding" => "gzip"]);

julia> Dict(r.headers)["content-encoding"]
"gzip"

julia> close(server)

See the compression guide.

Facil.compressible_type — Function
Facil.compressible_type(content_type) -> Bool

The default test CompressOptions uses to decide whether a response of this content-type is worth compressing. Parameters (; charset=...) are ignored.

true for text/*, any +json or +xml type, image/svg+xml, TrueType and OpenType fonts, and application/ json, javascript, xml, wasm, x-ndjson, graphql, x-www-form-urlencoded, yaml, toml, sql and a few more. false for formats that are already compressed (images, video, archives, WOFF fonts).

julia> using Facil

julia> Facil.compressible_type("application/json; charset=utf-8")

julia> Facil.compressible_type("image/png")

julia> mine(ct) = Facil.compressible_type(ct) || ct == "application/x-custom";

julia> CompressOptions(; compressible = mine) isa CompressOptions

Facil.compress_response — Function
Facil.compress_response(req, res, opts::CompressOptions)

Apply opts to one handler result, as a server started with serve!(...; compress = opts) does for every result.

Returns a new Response with a compressed body and content-encoding when res qualifies (see CompressOptions), a stream response with its encoding chosen, or res itself. Call it in a handler to compress only some routes on a server started without compress.

Examples

julia> using Facil

julia> req = Request(Methods.GET, "/"; headers = ["accept-encoding" => "gzip"]);

julia> res = Facil.compress_response(req, Response(StatusCodes.OK, "hello "^1000), CompressOptions());

julia> String(headers(res)["content-encoding"])
"gzip"

julia> sizeof(body(res)) < 100
true

Facil.gzip — Function
Facil.gzip(data; level = 6) -> Vector{UInt8}

Compress data (a String or byte vector) as one gzip member (RFC 1952) with libdeflate. level is 1 (fastest) to 12 (smallest). This is what compress = true uses for whole bodies; call it yourself to precompress a response you cache.
