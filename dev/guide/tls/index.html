HTTPS (TLS)

This page shows how to serve HTTPS: building a TLSConfig, choosing certificates by host name, requiring client certificates, and replacing a certificate while the server runs. Everything else on a server (handlers, streaming, WebSockets as wss://) works the same over TLS.

Facil uses OpenSSL 3 through Julia's own OpenSSL_jll; you do not install anything.

A certificate for development

For local work, make a self-signed certificate with the openssl command:

openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem -days 365 \
    -subj "/CN=localhost" -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"

This writes cert.pem and an unencrypted key.pem. Browsers and clients will not trust it unless you tell them to (curl --cacert cert.pem). For a public server, get a certificate from a certificate authority, for example with an ACME client such as certbot.

Serve HTTPS

Build a TLSConfig from the certificate and key and pass it as tls:

using Facil

# Paths to a PEM certificate (chain, leaf first) and its private key.
cert = get(ENV, "TLS_CERT", "cert.pem")
key = get(ENV, "TLS_KEY", "key.pem")

# Reads and checks both files now: a missing file, a wrong password or a key
# that does not match the certificate throws here, before the server starts.
tls = TLSConfig(cert, key; min_version = v"1.2")

serve("127.0.0.1", 8443; tls) do req
    Response(StatusCodes.OK, "secure hello\n")
end
$ curl --cacert cert.pem https://127.0.0.1:8443/
secure hello

cert and key are each a file path or the PEM text itself (anything containing -----BEGIN). The certificate may hold the whole chain, leaf first, then intermediates.

A server is either HTTP or HTTPS. To serve both, start two servers; they share the reactor:

  • one with tls on 443,
  • one without on 80 whose handler redirects to https://.

A plain-HTTP request sent to the HTTPS port fails the TLS handshake and gets no HTTP answer.

HTTPS needs `reactors = 1`

TLS connections are only safe on one reactor thread. serve! with tls and reactors > 1 throws an ArgumentError, and so does an HTTPS server in a process whose reactor already runs several threads. Handlers still run on all Julia threads (inline = false); only socket I/O and encryption are on the single reactor thread.

Errors show up early

TLSConfig reads the files and checks every certificate against its key when you construct it, not at the first connection. What it throws:

ProblemException
File missing, or it holds no PEM dataArgumentError
Key does not match the certificateTLSError
Encrypted key, wrong or missing passwordTLSError
OpenSSL rejects the versions, ciphers or ciphersuitesTLSError
require_client_cert = true without client_caArgumentError
max_version below min_version, or not a TLS versionArgumentError

A TLSError message carries OpenSSL's own reason, for example TLSError: certificate: the private key does not match the certificate (error:05800074:x509 certificate routines::key values mismatch).

Because the files are read at construction, a TLSConfig keeps working if the files are later moved or deleted, and does not notice when they change. See Replace a certificate.

Options

KeywordDefaultMeaning
passwordnothingPassphrase of an encrypted key. Also used for sni entries that give none.
sni[]Extra certificates chosen by host name; see below.
min_versionv"1.2"Lowest protocol version accepted: v"1.0", v"1.1", v"1.2" or v"1.3".
max_versionnothingHighest version accepted; nothing means the newest OpenSSL supports.
ciphersnothingOpenSSL cipher list for TLS 1.2 and below. nothing keeps OpenSSL's default.
ciphersuitesnothingCipher suites for TLS 1.3.
prefer_server_ciphersfalseUse the server's cipher order instead of the client's.
client_canothingCA certificates (path or PEM) that client certificates must chain to.
require_client_certfalseRefuse clients that present no certificate. Needs client_ca.

Keep min_version at v"1.2" or raise it to v"1.3". TLS 1.0 and 1.1 are obsolete; with OpenSSL 3 they also need ciphers = "DEFAULT@SECLEVEL=0" to work at all.

The server offers only http/1.1 through ALPN. There is no HTTP/2.

Several certificates (SNI)

One server can present different certificates depending on the host name the client asks for. Each sni entry is (host, cert, key) or (host, cert, key, password). host may be a wildcard such as "*.b.test". Names without an entry get the default certificate.

using Facil

certs = get(ENV, "TLS_DIR", "certs")
pem(name) = joinpath(certs, name)

# The default certificate answers every name that has no entry in `sni`.
tls = TLSConfig(get(ENV, "TLS_CERT", "cert.pem"), get(ENV, "TLS_KEY", "key.pem");
                # (host, cert, key) or (host, cert, key, password); the host may be a wildcard
                sni = [("a.test", pem("a_cert.pem"), pem("a_key.pem")),
                       ("*.b.test", pem("b_cert.pem"), pem("b_key.pem"))],
                min_version = v"1.2",
                prefer_server_ciphers = true)

serve("127.0.0.1", 8443; tls) do req
    # The name the client asked for is not passed to the handler; use the Host header.
    Response(StatusCodes.OK, "hello " * as_str(get(headers(req), header.HOST, hv"?")) * "\n")
end

The handler does not receive the negotiated name. Route on the Host header, which clients send with the same name.

Client certificates (mutual TLS)

Give client_ca to verify the certificates clients present. A client whose certificate was not signed by that CA is refused during the handshake. With require_client_cert = true, a client that presents no certificate is refused too; without it, such clients are let in.

using Facil

tls = TLSConfig(get(ENV, "TLS_CERT", "cert.pem"), get(ENV, "TLS_KEY", "key.pem");
                client_ca = get(ENV, "TLS_CLIENT_CA", "clients_ca.pem"),   # certificates must be signed by this CA
                require_client_cert = true)                                # and every client must present one

serve("127.0.0.1", 8443; tls) do req
    Response(StatusCodes.OK, "hello, trusted client\n")
end
$ curl --cacert cert.pem --cert client_cert.pem --key client_key.pem https://127.0.0.1:8443/
hello, trusted client

A refused client sees a failed handshake, not an HTTP status, and your handler is not called. The client's certificate (subject, fingerprint) is not available to the handler, so you can admit a set of clients by CA but not tell them apart.

Replace a certificate without restarting

reload!(server; cert, key) swaps the certificate of a running HTTPS server. Connections made from then on get the new certificate; open connections keep the one they started with. If the pair is bad, reload! throws (as TLSConfig would) and the server keeps its current certificate.

  • host = "name" replaces the sni entry of that name, or adds one. Without host, the default certificate is replaced.
  • password unlocks an encrypted key.
  • On a server without tls, or one that is closed, reload! throws an ArgumentError.

Certificates are usually renewed by another program that rewrites the files. This example checks the certificate file once a minute and reloads when it changed:

using Facil

# Reloads the certificate whenever its file changes (for example after a
# renewal by certbot). Checks once a minute; returns the timer.
function watch_certificate(server::Server, cert::AbstractString, key::AbstractString; interval_ms = 60_000)
    seen = Ref(mtime(cert))
    every(interval_ms) do
        isopen(server) || return false          # stop with the server
        m = mtime(cert)
        m == seen[] && return true
        try
            reload!(server; cert, key)          # new connections get the new certificate
            seen[] = m
            println(stderr, "certificate reloaded")
        catch e
            # A bad pair (say, the key is not written yet) changes nothing; try again next time.
            println(stderr, "certificate not reloaded: ", sprint(showerror, e))
        end
        true
    end
end

function main()
    cert = get(ENV, "TLS_CERT", "cert.pem")
    key = get(ENV, "TLS_KEY", "key.pem")
    server = serve!("127.0.0.1", 8443; tls = TLSConfig(cert, key)) do req
        Response(StatusCodes.OK, "secure hello\n")
    end
    watch_certificate(server, cert, key)
    wait(server)
end

abspath(PROGRAM_FILE) == @__FILE__() && main()

The renewal tool may write the certificate and the key a moment apart. The watcher handles that: a mismatched pair makes reload! throw, nothing changes, and the next check tries again.

Behind a reverse proxy

If nginx, Caddy or a load balancer terminates TLS in front of Facil, serve plain HTTP on a loopback or private address and leave certificates to the proxy. See Deployment.
