Coming from Node.js and Express

This page is for readers who know Node's http module, Express or ws. It maps what you know to Facil, points out where the model differs, and ports a small Express app. The Node code on this page is for comparison and is not run by this documentation's tests; the Julia code is.

The model in one paragraph

In Node you get a request and a response object and call methods on the response (res.writeHead, res.end). In Facil a handler is a function that returns the response:

using Facil

serve("127.0.0.1", 8080) do req
    Response(StatusCodes.OK, "hello")
end

There is no res to write to and no next(). For bodies that are produced over time you return a stream or sse response whose function does the writing. The other large difference is threads: Node runs your JavaScript on one thread, while Facil's task handlers run on several Julia threads at once, so shared state needs a lock or atomics.

Differences to keep in mind:

  • content-length is always set by Facil. A String body without a content-type is sent as text/plain; charset=utf-8, bytes as application/octet-stream.
  • Response(404) with only an integer throws: it could mean a status or a body. Write Response(StatusCodes.NOT_FOUND). With a body, an integer status is fine: Response(404, "not found").
  • A response body is sent without a copy. Do not modify a Vector{UInt8} after returning it.
  • An uncaught exception becomes a 500 and the server keeps running; there is no process crash to guard against as with an unhandled 'error' event. See Errors and logging.

Middleware

Express middleware calls next(). In Facil a middleware is a function that takes a handler and returns a handler; it calls the inner handler and may change what goes in or comes out.

ExpressFacil
app.use(mw)serve(mw(app), ...)
app.use(a); app.use(b)serve(a(b(app)), ...) — a sees the request first and the response last
error-handling middleware (err, req, res, next)a wrapper with try/catch around the inner handler

An Express app, ported

Express:

const express = require('express');
const app = express();
app.use(express.json());
app.use((req, res, next) => {
  res.on('finish', () => console.log(req.method, req.url, '->', res.statusCode));
  next();
});

const users = new Map([[1, 'ada'], [2, 'grace']]);

app.get('/users', (req, res) => {
  res.json([...users].map(([id, name]) => ({ id, name })));
});

app.get('/users/:id', (req, res) => {
  const name = users.get(Number(req.params.id));
  if (!name) return res.status(404).json({ error: 'no such user' });
  res.json({ id: Number(req.params.id), name });
});

app.post('/users', (req, res) => {
  if (typeof req.body.name !== 'string') return res.status(400).json({ error: 'name is required' });
  const id = Math.max(0, ...users.keys()) + 1;
  users.set(id, req.body.name);
  res.status(201).json({ id, name: req.body.name });
});

app.use((req, res) => res.status(404).json({ error: 'not found' }));
app.listen(8080);

Facil, with the forty lines of Express that this app relies on written out (a json helper, a route table with :param segments, a logger):

using Facil, JSON

# ---- a few lines that stand in for Express ----

json(data; status = StatusCodes.OK) =                       # res.status(s).json(data)
    Response(status, JSON.json(data); headers = [header.CONTENT_TYPE => "application/json"])

struct Route
    method::HttpMethod
    segments::Vector{String}                                # "/users/:id" -> ["users", ":id"]
    handler::Function
end

const ROUTES = Route[]
route(handler, m::HttpMethod, pattern::String) =            # app.get(pattern, handler)
    push!(ROUTES, Route(m, split(pattern, '/'; keepempty = false), handler))

function match_route(r::Route, segments)
    length(r.segments) == length(segments) || return nothing
    params = Dict{String,String}()
    for (pattern, value) in zip(r.segments, segments)
        if startswith(pattern, ':')
            params[pattern[2:end]] = value                  # req.params
        elseif pattern != value
            return nothing
        end
    end
    params
end

function router(req)
    segments = split(path(uri(req)), '/'; keepempty = false)
    for r in ROUTES
        r.method == method(req) || continue
        params = match_route(r, segments)
        params === nothing || return r.handler(req, params)
    end
    json(Dict("error" => "not found"); status = StatusCodes.NOT_FOUND)
end

# Middleware is a function that takes a handler and returns a handler.
function logger(next)                                       # app.use((req, res, next) => ...)
    function (req)
        res = next(req)
        println(method(req), ' ', uri(req), " -> ", Int(status(res)))
        res
    end
end

# ---- the application ----

const USERS = Dict(1 => "ada", 2 => "grace")
const USERS_LOCK = ReentrantLock()                          # handlers run on several threads

route(Methods.GET, "/users") do req, params
    json(lock(() -> [Dict("id" => id, "name" => name) for (id, name) in sort!(collect(USERS))], USERS_LOCK))
end

route(Methods.GET, "/users/:id") do req, params
    id = tryparse(Int, params["id"])
    name = id === nothing ? nothing : lock(() -> get(USERS, id, nothing), USERS_LOCK)
    name === nothing && return json(Dict("error" => "no such user"); status = StatusCodes.NOT_FOUND)
    json(Dict("id" => id, "name" => name))
end

route(Methods.POST, "/users") do req, params
    data = try
        JSON.parse(body(req))                               # express.json()
    catch
        return json(Dict("error" => "invalid JSON"); status = StatusCodes.BAD_REQUEST)
    end
    data isa AbstractDict && get(data, "name", nothing) isa AbstractString ||
        return json(Dict("error" => "name is required"); status = StatusCodes.BAD_REQUEST)
    id = lock(USERS_LOCK) do
        id = maximum(keys(USERS); init = 0) + 1
        USERS[id] = data["name"]
        id
    end
    json(Dict("id" => id, "name" => data["name"]); status = StatusCodes.CREATED)
end

serve(logger(router), "127.0.0.1", 8080)                    # app.listen(8080)
$ curl http://127.0.0.1:8080/users/2
{"id":2,"name":"grace"}
$ curl -X POST -d '{"name":"linus"}' http://127.0.0.1:8080/users
{"id":3,"name":"linus"}
$ curl http://127.0.0.1:8080/
{"error":"not found"}

(The order of keys in the JSON output depends on the JSON package.)

What changed in the port, besides syntax:

  • The lock. Task handlers run on several threads, so the USERS dictionary is guarded. In Node the single thread made that unnecessary.
  • Explicit JSON errors. express.json() answers malformed JSON with a 400 for you; here the handler does.
  • Start-up. Run with threads: julia -t 4 server.jl. With one thread, handlers run inline on the reactor.

By default WebSocket callbacks run on the reactor thread, much like Node's event loop: they must not block. Pass spawn = true to run them on tasks. See WebSockets.

Server-sent events

Node has no built-in helper; you write text/event-stream by hand. Facil has one: return sse(req) do s ... end and call write_event(s; data, event, id). See Server-sent events.

Processes, cores and signals

Node.jsFacil
one event-loop threadone reactor thread by default; reactors = N for more
cluster / several processes behind a balancernot available (no fork); use Julia threads (julia -t N) for handlers and reactors for I/O
worker_threads for CPU-heavy worktask handlers already run on Julia threads
blocking the event loop is a bugstill a bug for inline handlers and reactor callbacks; fine in task handlers
async/awaitnot needed: a task handler just blocks (Facil.sleep, I/O, locks) and other requests proceed
process.on('SIGTERM', () => server.close())built into serve: SIGTERM drains for shutdown_grace seconds
process.on('SIGINT', ...)not catchable from a script; see Graceful shutdown

Two things cost more than in Node, and are worth knowing before you measure: start-up (seconds, because Julia compiles your handler on first use) and memory at rest. Steady-state throughput is compared row by row in Benchmarks.
