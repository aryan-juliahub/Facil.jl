Testing a Facil app

This page shows two ways to test a Facil application with Julia's Test standard library: calling the handler directly with a request you build, and running a real server on a free port and talking to it over HTTP. Use the first for most tests and the second for a few end-to-end checks.

Structure your app for testing

Write the handler as a named function, and keep the serve call out of the code your tests load: put it in a main() function or a separate script. Tests can then load the application without starting a server. The application used on this page:

# The application: a plain function from a request to a response.
function app(req)
    m, p = method(req), path(uri(req))
    if m == Methods.GET && p == "/health"
        Response(StatusCodes.OK, "ok")
    elseif m == Methods.POST && p == "/shout"
        isempty(body(req)) && return Response(StatusCodes.BAD_REQUEST, "empty body")
        Response(StatusCodes.OK, uppercase(body(req)); headers = [header.CONTENT_TYPE => "text/plain"])
    else
        Response(StatusCodes.NOT_FOUND, "not found")
    end
end

Unit tests: call the handler

A handler takes a Request and returns a Response. Build the first, inspect the second. No server runs, so these tests are fast and cannot fail on a busy port.

# Unit tests: build a request, call the handler, look at the response.
# No server, no sockets. Pass `body = ""` for requests without a body, as the
# server does, so the handler sees a `Request{String}`.
@testset "handler" begin
    res = app(Request(Methods.GET, "/health", ""))
    @test status(res) == StatusCodes.OK
    @test body(res) == "ok"

    res = app(Request(Methods.POST, "/shout", "hello"; headers = ["content-type" => "text/plain"]))
    @test status(res) == 200
    @test body(res) == "HELLO"
    @test headers(res)[header.CONTENT_TYPE] == "text/plain"

    @test status(app(Request(Methods.POST, "/shout", ""))) == StatusCodes.BAD_REQUEST
    @test status(app(Request(Methods.DELETE, "/health", ""))) == StatusCodes.NOT_FOUND
end

Building requests:

  • Request(method, target, body; headers = [...]). The method may be a constant (Methods.POST) or a string ("POST"); the target is a string such as "/items?page=2".
  • Pass "" as the body of requests that have none. The server always hands handlers a Request{String} whose body is "" when the client sent none; Request(Methods.GET, "/health") without a body argument makes a Request{Nothing} instead, and isempty(body(req)) would throw.
  • Headers are name => value pairs. Names are case-insensitive.

Inspecting responses:

  • status(res) compares equal to both StatusCodes.OK and 200.
  • body(res) is whatever the handler put in: a String, a Vector{UInt8} or nothing.
  • headers(res)[header.CONTENT_TYPE] (or "content-type") is the value; it compares equal to a string. Use get(headers(res), name, nothing) when the header may be absent.
  • A handler may return a plain String. If yours does, test for that, or normalise with res isa Response ? res : Response(StatusCodes.OK, res).

What unit tests do not cover is everything the server adds: the default content-type, content-length, limits, before_body, compression, and the bodies of stream, sse and sendfile responses (their body(res) is an internal object, not the bytes). Test those end to end.

End-to-end tests: a real server

Start the app with serve! on port 0, which picks a free port; ask the server which one with port(server); close it in a finally block so a failing test does not leave it running.

Any HTTP client works. Downloads ships with Julia, so it needs no extra dependency; a small wrapper makes it convenient:

# A small client on Downloads (a standard library): returns the status and the body.
function fetch_url(url; method = "GET", body = nothing, headers = Pair{String,String}[])
    out = IOBuffer()
    input = body === nothing ? nothing : IOBuffer(body)
    res = Downloads.request(url; method, input, output = out, headers, throw = false)
    res isa Downloads.RequestError && throw(res)
    (status = res.status, headers = Dict(res.headers), body = String(take!(out)))
end
`import Downloads`, not `using Downloads`

Downloads exports a type called Response, and so does Facil. With using Facil, Downloads in one module, the name Response is ambiguous and using it throws an UndefVarError. Write import Downloads and qualify its functions (Downloads.request).

# End-to-end tests: a real server on a free port (port 0), closed in `finally`.
@testset "server" begin
    server = serve!(app, "127.0.0.1", 0)
    try
        base = "http://127.0.0.1:$(port(server))"

        res = fetch_url(base * "/health")
        @test res.status == 200
        @test res.body == "ok"
        @test res.headers["content-type"] == "text/plain; charset=utf-8"

        res = fetch_url(base * "/shout"; method = "POST", body = "hello")
        @test res.status == 200
        @test res.body == "HELLO"

        @test fetch_url(base * "/nope").status == 404
    finally
        close(server)
        wait(server)
    end
end

The whole file runs as a test script:

$ julia -t 4 --project testing_app.jl
Test Summary: | Pass  Total
handler       |    7      7
Test Summary: | Pass  Total
server        |    6      6

Tips

  • Never use a fixed port in tests. Port 0 lets parallel test runs and CI machines coexist. serve! throws a SystemError if a fixed port is taken.
  • Close and wait. close(server) returns at once; wait(server) blocks until the port is released (up to about a second). Skip the wait when nothing after it depends on the port.
  • One reactor per process. All servers in a test process share it, and the first server fixes reactors. A test that needs a different reactors value must run in its own process.
  • Threads. Run tests with several threads (julia -t 4 --project -e 'using Pkg; Pkg.test()') if your app relies on task handlers. With one thread every handler runs inline, and a handler that waits for another request to the same server would deadlock.
  • Inline servers. For inline = true apps, start the test server with inline = true as well, so blocking mistakes show up as stalls in tests.
  • Slow first request. The first request compiles your handler. Give time-outs in CI some slack, or make one warm-up request before timing anything.
  • Asserting on logs. Facil writes errors to file descriptor 2, not through Logging, so @test_logs does not see them. Test the response instead.

Testing WebSocket code

Julia's standard library has no WebSocket client, and Facil does not include one. Two approaches work:

  1. Keep what a message does in a function of plain values and test that function directly. The callbacks become one-liners that need no test.
  2. For end-to-end tests, add a WebSocket client package to your test dependencies and connect to ws://127.0.0.1:$(port(server))/.

The first approach:

# Keep what a message does in a function of plain values...
function reply(history::Vector{String}, msg::String)
    msg == "/count" && return "$(length(history)) messages so far"
    push!(history, msg)
    "echo: $msg"
end

# ...so the callbacks only connect it to the socket.
function app(req)
    websocket(req;
              on_open = ws -> (ws.data = String[]),
              on_message = (ws, msg) -> send(ws, reply(ws.data, msg)))
end
@testset "reply" begin
    history = String[]
    @test reply(history, "a") == "echo: a"
    @test reply(history, "b") == "echo: b"
    @test reply(history, "/count") == "2 messages so far"
    @test history == ["a", "b"]
end

@testset "upgrade" begin
    # A request that is not a WebSocket upgrade is answered 400 by the server;
    # the handler's own routing can be tested with Facil.is_upgrade.
    plain = Request(Methods.GET, "/", "")
    upgrade = Request(Methods.GET, "/", ""; headers = ["upgrade" => "websocket", "connection" => "Upgrade"])
    @test !Facil.is_upgrade(plain)
    @test Facil.is_upgrade(upgrade)
end

A WebSocket cannot be constructed in a test, which is why the logic takes the history vector rather than ws.
