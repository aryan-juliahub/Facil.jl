Sending responses

This page shows what a handler may return and what Facil puts on the wire for it: the status line, the headers Facil and facil.io add, and the body. Bodies that are produced over time have their own pages: Streaming responses, Server-sent events and Static files.

What a handler may return

The handler returnsThe client gets
a Response with a String bodythat status, those headers, the string's bytes
a Response with a Vector{UInt8} bodythe same, with the bytes
a Response with body nothing (or an empty body)status and headers, content-length: 0 (no content-length for 1xx, 204 and 304)
a String200 OK, text/plain; charset=utf-8
stream(f, req)a body written piece by piece; see Streaming responses
sse(f, req)an event stream; see Server-sent events
sendfile(path)a file; see Static files
websocket(req; ...)a WebSocket upgrade; see WebSockets
anything else, or it throws500 Internal Server Error

Other AbstractString and AbstractVector{UInt8} bodies (a SubString, a view) are accepted and copied into a String or Vector{UInt8} first.

One server showing most of these:

using Facil

const PNG_PIXEL = UInt8[0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a]

function app(req)
    p = path(uri(req))
    if p == "/text"
        "a plain String is a 200 text/plain response\n"
    elseif p == "/html"
        Response(StatusCodes.OK, "<h1>hello</h1>\n"; headers = [header.CONTENT_TYPE => "text/html; charset=utf-8"])
    elseif p == "/bytes"
        Response(StatusCodes.OK, PNG_PIXEL; headers = [header.CONTENT_TYPE => "image/png"])
    elseif p == "/created"
        Response(StatusCodes.CREATED, "made\n"; headers = [header.LOCATION => "/things/1", "x-request-id" => "42"])
    elseif p == "/empty"
        Response(StatusCodes.NO_CONTENT)
    elseif p == "/old"
        Response(StatusCodes.MOVED_PERMANENTLY; headers = [header.LOCATION => "/text"])
    elseif p == "/cookies"
        res = Response(StatusCodes.OK, "two cookies\n")
        append!(headers(res), header.SET_COOKIE, "a=1; Path=/")
        append!(headers(res), header.SET_COOKIE, "b=2; Path=/")
        res
    elseif p == "/busy"
        Response(503, "an integer status works when a body follows\n"; headers = [header.RETRY_AFTER => "30"])
    elseif p == "/boom"
        error("handlers that throw give a 500")
    else
        Response(StatusCodes.NOT_FOUND, "no such page\n")
    end
end

serve(app, "127.0.0.1", 8080)

Building a Response

Response comes from HttpTypes. The forms you will use most:

using Facil

Response(StatusCodes.OK, "hello")                       # status and body
Response{String}(status=StatusCodes.OK, version=Versions.HTTP_11, headers=HeaderMap(), body="hello")
Response(StatusCodes.NO_CONTENT)                        # status only, body `nothing`
Response{Nothing}(status=StatusCodes.NO_CONTENT, version=Versions.HTTP_11, headers=HeaderMap(), body=nothing)
Response(StatusCodes.CREATED, "made";                   # with headers
         headers = [header.LOCATION => "/things/1", "x-request-id" => "42"])
Response{String}(status=StatusCodes.CREATED, version=Versions.HTTP_11, headers=HeaderMap(hn"location" => hv"/things/1", hn"x-request-id" => hv"42"), body="made")

The status is a StatusCode. Use the constants in StatusCodes (StatusCodes.NOT_FOUND), or an integer when a body follows: Response(404, "no such page").

`Response(404)` throws

A single integer argument is ambiguous (is it a status or a body?), so Response(404) throws an ArgumentError. Write Response(StatusCodes.NOT_FOUND) for a response with that status and no body. Response("text"), a single non-status argument, is a 200 with that body.

A response is mutable. Build it, then adjust it:

res = Response(StatusCodes.OK, "two cookies")
append!(headers(res), header.SET_COOKIE, "a=1; Path=/")
append!(headers(res), header.SET_COOKIE, "b=2; Path=/")
res.status = 202
res
Response{String}(status=StatusCodes.ACCEPTED, version=Versions.HTTP_11, headers=HeaderMap(hn"set-cookie" => hv"a=1; Path=/", hn"set-cookie" => hv"b=2; Path=/"), body="two cookies")

Status

Facil sends the status code you return, whatever it is from 100 to 999, with its standard reason phrase: canonical_reason(status), such as 418 I'm a teapot. A code that has no standard phrase (299, 599) is sent as 299 Unknown.

1xx, 204 and 304 responses never carry content. Facil sends them without a body, without content-length and without a default content-type, even if the Response was built with a body; the headers you set (etag, cache-control, ...) are kept. Build them with Response(StatusCodes.NO_CONTENT).

Interim responses are not available to handlers: 100 Continue is sent by Facil (see Reading requests), and there is no way to send 103 Early Hints before the final response.

Headers

Pass headers as any iterable of name => value pairs, or change headers(res) afterwards with insert! (replace), append! (add a second line of the same name) and delete!. Names may be strings or the constants in header; they are validated and lowercased when the response is built, and an invalid name or value throws there (InvalidHeaderName, InvalidHeaderValue), inside your handler, where you can see it.

Header names go out in lowercase. That is valid HTTP (names are case-insensitive), but a client that compares names case-sensitively will miss them.

Facil and facil.io complete the head:

HeaderRule
content-lengthalways set by Facil from the body; a value you set is ignored
transfer-encodingset by Facil for streamed responses; a value you set is ignored
content-typeif you set none and the body is not empty: text/plain; charset=utf-8 for a string body, application/octet-stream for a byte body
dateadded by facil.io when you set none (not on streamed responses)
last-modifiedadded by facil.io, with the current time, when you set none (not on streamed responses)
connectionkeep-alive or close, added by facil.io when you set none
`last-modified` on dynamic responses

Every response that is not streamed gets last-modified set to the time it was sent unless you set the header yourself. A cache may use it for heuristic freshness. Set cache-control (for example no-store) on responses that must not be cached, or set last-modified to the real time your data changed.

To close the connection after a response, set connection: close on it.

Bodies are sent without a copy

A String or Vector{UInt8} body is handed to the socket as it is: Facil keeps the object alive until the last byte has been written and never copies it. This is why large responses are cheap, and it has one rule:

Do not change a body after returning it

A Vector{UInt8} that you return (or write to a stream) may still be on its way to the client after your handler has returned. Do not write into it, resize! it or put it back into a buffer pool. Returning the same constant body from many requests at once is fine.

Strings are immutable, so this only concerns byte vectors.

Redirects, errors and empty responses

A redirect is a status and a location header:

Response(StatusCodes.SEE_OTHER; headers = [header.LOCATION => "/login"])
Response{Nothing}(status=StatusCodes.SEE_OTHER, version=Versions.HTTP_11, headers=HeaderMap(hn"location" => hv"/login"), body=nothing)

For errors, return the status you mean. Nothing is added to a body you send, so an API can use its own error format:

Response(StatusCodes.NOT_FOUND, """{"error":"no such user"}""";
         headers = [header.CONTENT_TYPE => "application/json"])
Response{String}(status=StatusCodes.NOT_FOUND, version=Versions.HTTP_11, headers=HeaderMap(hn"content-type" => hv"application/json"), body="{\"error\":\"no such user\"}")

When the handler fails

If the handler throws, returns something that is not in the table above, or returns a response whose body Facil cannot send, the client gets a 500 Internal Server Error whose body is the text Internal Server Error (text/plain; charset=utf-8).

The connection stays open for the next request. The error and its stack trace are written to stderr, at most once per exception type every 10 seconds; see Errors and logging. Nothing about the error is sent to the client. To send your own error body, catch the exception in the handler and return a response.

HEAD requests

For a HEAD request Facil sends the head of whatever the handler returned and leaves the body out; content-length is the length the body would have had. The handler still runs and still builds the body, so check for Methods.HEAD yourself when the body is expensive.
