JSON

This page shows how to receive and send JSON. Facil has no JSON code of its own: the body of a request is a String and the body of a response is a String or bytes, so any JSON package fits between them. The examples use JSON.jl version 1; JSON3.jl and others work the same way.

For a complete JSON API with routing, storage and tests, follow the tutorial. This page is the reference for the JSON part.

A JSON endpoint

using Facil, JSON

const JSON_TYPE = [header.CONTENT_TYPE => "application/json"]

json_response(status, data) = Response(status, JSON.json(data); headers = JSON_TYPE)

# The request body as parsed JSON, or `nothing` when it is not JSON.
function json_body(req)
    try
        JSON.parse(body(req))
    catch
        nothing
    end
end

function is_json(req)
    ct = get(headers(req), header.CONTENT_TYPE, nothing)
    ct !== nothing && startswith(lowercase(as_str(ct)), "application/json")
end

serve("127.0.0.1", 8080; body_in_memory = 1024 * 1024) do req
    m, p = method(req), path(uri(req))
    if m == Methods.GET && p == "/status"
        json_response(StatusCodes.OK, (status = "ok", julia = string(VERSION)))
    elseif m == Methods.POST && p == "/greet"
        is_json(req) || return json_response(StatusCodes.UNSUPPORTED_MEDIA_TYPE, (error = "send application/json",))
        data = json_body(req)
        data isa AbstractDict || return json_response(StatusCodes.BAD_REQUEST, (error = "the body must be a JSON object",))
        name = get(data, "name", nothing)
        name isa AbstractString || return json_response(StatusCodes.UNPROCESSABLE_ENTITY, (error = "name must be a string",))
        json_response(StatusCodes.CREATED, Dict("greeting" => "hello $name", "length" => length(name)))
    else
        json_response(StatusCodes.NOT_FOUND, (error = "not found",))
    end
end
$ curl http://127.0.0.1:8080/greet -H 'Content-Type: application/json' -d '{"name":"Ada"}'
{"greeting":"hello Ada","length":3}
$ curl http://127.0.0.1:8080/greet -H 'Content-Type: application/json' -d '{not json'
{"error":"the body must be a JSON object"}

Sending JSON

Serialise to a String and set the content type yourself:

using Facil, JSON

res = Response(StatusCodes.OK, JSON.json((status = "ok", items = [1, 2, 3]));
               headers = [header.CONTENT_TYPE => "application/json"])
body(res)
"{\"status\":\"ok\",\"items\":[1,2,3]}"
  • Set content-type. Without it Facil labels a String body text/plain; charset=utf-8, and browsers and HTTP clients will not treat it as JSON. JSON is UTF-8 by definition; application/json needs no charset.
  • content-length is set by Facil.
  • JSON.json accepts named tuples, dictionaries, vectors, numbers, strings, nothing (as null) and your own structs (as objects of their fields).
  • A helper such as json_response(status, data) in the example keeps the header in one place. Build the header vector once (a const) if you like; each response still gets its own header map.

For large responses, turn on compression: JSON compresses well.

Reading JSON

body(req) is the request body as a String. Parse it:

req = Request(Methods.POST, "/greet", """{"name":"Ada","tags":["a","b"]}""";
              headers = [header.CONTENT_TYPE => "application/json"])

data = JSON.parse(body(req))
data["name"], data["tags"]
("Ada", Any["a", "b"])

JSON.parse returns objects as a dictionary type (JSON.Object{String,Any}), arrays as Vector{Any}, and numbers, strings, booleans and nothing. It can also parse straight into a struct:

struct Greeting
    name::String
    tags::Vector{String}
end

JSON.parse(body(req), Greeting)
Main.Greeting("Ada", ["a", "b"])

Three things go wrong with JSON from the network, and each deserves its own answer:

ProblemHow you noticeAnswer
The body is not JSON (or is empty)JSON.parse throws400
It is JSON but not the shape you expectit is an array where you wanted an object, a field is missing or has the wrong type400 or 422
The client sent something else (text/plain, a form)the content-type header415
Catch parse errors

An exception that escapes the handler becomes a 500 Internal Server Error and a stack trace in your log (see Errors and logging). Bad input from a client is not a server error: wrap the parse in try and answer 400, as json_body does in the example.

Check types before you use values. data["name"] on an array throws, and a "name" that is a number will break code that expects a string much later. The example checks data isa AbstractDict and name isa AbstractString before going on.

Checking the content type

The content-type header may carry parameters (application/json; charset=utf-8) and any letter case, so compare a lowercased prefix rather than the whole value:

function is_json(req)
    ct = get(headers(req), header.CONTENT_TYPE, nothing)
    ct !== nothing && startswith(lowercase(as_str(ct)), "application/json")
end

is_json(req), is_json(Request(Methods.POST, "/greet", "name=Ada"))
(true, false)

Large bodies

By default a request body is read into memory before the handler runs, up to body_in_memory (16 MiB); a larger body is answered with 413 by Facil and your handler is not called. A JSON API rarely needs megabytes: lower the limit to what you expect, as the example does with body_in_memory = 1024 * 1024. That 413 has a plain-text body, not your API's JSON error format.

JSON.parse needs the whole document, so there is nothing to gain from streaming a JSON body. For genuinely large uploads, take newline-delimited JSON and parse it line by line from body_stream(req); see Request bodies and uploads.

For large JSON responses, building the string is usually the dominant cost, not sending it (the benchmarks record this for a 50 KB response; see Benchmarks). If the document does not change between requests, serialise it once and return the same String every time: bodies are sent without a copy.
