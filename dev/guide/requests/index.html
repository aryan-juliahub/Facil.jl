Reading requests

This page shows how to read what the client sent: the method, the request target (path and query), the headers and the protocol version. It also lists what Facil answers by itself, before your handler is called. Request bodies have their own page: Request bodies and uploads.

What a handler receives

A handler is called with one argument, a Request{String} from HttpTypes. Facil builds it from the request head that facil.io parsed and, by default, the whole body.

AccessorTypeWhat it is
method(req)HttpMethodMethods.GET, Methods.POST, ... or an extension method
uri(req)Urithe request target: path(uri(req)) and query(uri(req))
version(req)VersionVersions.HTTP_11 or Versions.HTTP_10
headers(req)HeaderMapevery header line, names lowercased
body(req)Stringthe body bytes; "" when there is none
extensions(req)Extensionsper-request storage for your own values

The same values are fields (req.method, req.uri, ...). The request belongs to your handler: Facil keeps no reference to it, so you may change it, store it or pass it to another task.

This server answers every request with a description of what it received:

using Facil

function describe(req)
    h = headers(req)
    lines = [
        "method: $(method(req))",
        "path: $(path(uri(req)))",
        "query: $(something(query(uri(req)), "(none)"))",
        "version: $(version(req))",
        "host: $(h[header.HOST])",
        "user-agent: $(get(h, header.USER_AGENT, "(none)"))",
        "accept (all): $(join(get_all(h, "accept"), " | "))",
        "headers: $(length(h))",
        "body bytes: $(sizeof(body(req)))",
    ]
    Response(StatusCodes.OK, join(lines, "\n") * "\n")
end

serve(describe, "127.0.0.1", 8080)
$ curl -X POST 'http://127.0.0.1:8080/users/7?page=2&q=a%20b' -A demo -H 'Accept: text/html' -H 'ACCEPT: application/json' -d hello
method: POST
path: /users/7
query: page=2&q=a%20b
version: HTTP/1.1
host: 127.0.0.1:8080
user-agent: demo
accept (all): text/html | application/json
headers: 6
body bytes: 5

Method

method(req) is an HttpMethod. Compare it with the constants in Methods or with a string:

using Facil

req = Request(; method = "POST", uri = "/users/7?page=2&q=a%20b",
              headers = ["Host" => "example.com", "Accept" => "text/html", "ACCEPT" => "application/json"],
              body = "hello")

method(req) == Methods.POST, method(req) == "POST", is_safe(method(req))
(true, true, false)

The standard methods are OPTIONS, GET, POST, PUT, DELETE, HEAD, TRACE, CONNECT, PATCH and QUERY. Any other valid token reaches your handler as an extension method, so a request line PURGE /cache HTTP/1.1 gives method(req) == "PURGE". Answer methods you do not support with 405 and an allow header (see Routing).

HEAD

A HEAD request reaches your handler with method(req) == Methods.HEAD. Facil sends the status and headers your handler returns, with the content-length of the body, and drops the body. It does not turn HEAD into GET for you: a handler that branches on Methods.GET must also accept Methods.HEAD if you want HEAD answered like GET.

Request target: path and query

uri(req) is the request target as a Uri. For the usual origin-form target (/users/7?page=2) it has a path and maybe a query:

u = uri(req)
path(u), query(u)
("/users/7", "page=2&q=a%20b")
  • path(u) is the part before ?. It always starts with / (or is * for OPTIONS *).
  • query(u) is the part after ?, or nothing when the target has no query. A target that ends in a bare ? also gives nothing, and a #fragment is dropped.
  • A target in absolute form (GET http://example.com/a?x=1 HTTP/1.1, as proxies send) reaches your handler as /a?x=1: the scheme and host are dropped. Read the host from the host header.
Nothing is percent-decoded

Facil and HttpTypes hand you the path and query exactly as they were sent: /caf%C3%A9 stays /caf%C3%A9, and q=a%20b stays q=a%20b. They are not split into parameters either. Decode what you use, after you have split it: decoding first would turn an encoded / (%2F) or & (%26) into a separator.

URIs.jl decodes both. queryparams splits and decodes a query string into a Dict, and unescapeuri decodes one path segment:

using Facil, URIs

serve("127.0.0.1", 8080) do req
    q = queryparams(something(query(uri(req)), ""))
    name = get(q, "name", "world")
    n = something(tryparse(Int, get(q, "n", "1")), 1)
    1 <= n <= 10 || return Response(StatusCodes.BAD_REQUEST, "n must be between 1 and 10\n")
    segments = unescapeuri.(split(path(uri(req)), '/'; keepempty = false))
    Response(StatusCodes.OK, join(fill("hello $name", n), "\n") * "\nsegments: $(join(segments, ", "))\n")
end
$ curl 'http://127.0.0.1:8080/caf%C3%A9/menu?name=Ada%20L&n=2'
hello Ada L
hello Ada L
segments: café, menu

queryparams keeps the last value of a repeated key and decodes + as a space. Use URIs.queryparampairs when a key may repeat (tag=a&tag=b).

Headers

headers(req) is a HeaderMap: a multimap from HeaderName to HeaderValue. Names are stored lowercase, so lookups ignore case. A key may be a string or one of the constants in header, such as header.CONTENT_TYPE; the constants skip the name check and compare as integers.

h = headers(req)
h["host"], h[header.HOST], get(h, "X-Missing", nothing)
(hv"example.com", hv"example.com", nothing)
CallResult
h[name]the first value; throws KeyError when absent
get(h, name, default)the first value, or default
haskey(h, name)whether the header was sent
get_all(h, name)every value of a repeated header, in the order sent
length(h)number of header lines; keys_len(h) counts distinct names
for (name, value) in hevery line, values of one name together

A value is a HeaderValue, not a String. It prints and interpolates as its text and compares equal to a string; as_str(v) or String(v) gives the String when you need one (to call parse, startswith, a regex and so on). to_str(v) does the same but throws when the value has bytes outside visible ASCII.

accept = get_all(h, "accept")
String.(accept), h["host"] == "example.com", startswith(as_str(h["accept"]), "text/")
(["text/html", "application/json"], true, true)

Facil does not join repeated headers or split comma-separated lists, and it does not parse cookies, authorization or content-type parameters. A request with two Accept lines has two values under accept; h["accept"] is the first.

Version

version(req) is Versions.HTTP_11 or Versions.HTTP_10. Facil speaks only HTTP/1.x. A request from an HTTP/1.0 client is answered and its connection is closed, unless the client asked for Connection: keep-alive. Versions are ordered, so version(req) < Versions.HTTP_11 tests for an old client.

Storing your own values on a request

extensions(req) holds at most one value per type. Use it to hand data from one layer of your code to the next (an authenticated user, a request id) without a global:

struct RequestId
    value::String
end

insert!(extensions(req), RequestId("7f3a"))
get(extensions(req), RequestId).value
"7f3a"

What Facil answers without calling your handler

Some requests never reach the handler. Facil or facil.io answers them and, with verbose = true, logs a line to stderr.

RequestAnswerConnection
No Host header (HTTP/1.1 and HTTP/1.0 alike)400kept
A target or header name that HttpTypes rejects400kept
Request head over max_header_size (32 KiB), one header line over about 8 KiB, or more than 128 headers431closed
Declared body over max_body_size (50 MiB)413closed
Buffered body over body_in_memory (16 MiB)413closed
before_body returned Reject(status)that statusclosed
Request head still arriving after header_timeout (30 s)408closed
Connection silent for timeout (40 s), with or without part of a headnoneclosed
A GET, HEAD or OPTIONS for a file in public_folderthe filekept

The error bodies are the reason phrase as text/plain (Payload Too Large). You cannot change them from the handler; put a reverse proxy in front if you need custom error pages for these cases.

The limits are keywords of serve!:

using Facil

serve("127.0.0.1", 8080;
      max_header_size = 8 * 1024,      # 431 above this
      max_body_size = 1024 * 1024,     # 413 above this, whatever before_body says
      body_in_memory = 64 * 1024,      # 413 above this for buffered bodies
      header_timeout = 10,             # 408 when the head takes longer
      timeout = 15) do req             # idle keep-alive connections are closed
    Response(StatusCodes.OK, "$(sizeof(body(req))) bytes\n")
end

Expect: 100-continue needs no code: Facil sends 100 Continue as soon as it has accepted the request head (after max_body_size and before_body have had their say), then reads the body. A request it refuses gets its 413 instead, so the client never sends the body.

A client that goes away

Facil does not tell a running handler that its client has disconnected. The handler finishes and its response is dropped. Only streamed responses and event streams can see it, through isopen; see Streaming responses.
